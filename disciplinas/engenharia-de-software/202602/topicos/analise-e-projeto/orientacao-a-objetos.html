“As classes estão para os objetos assim como as plantas arquitetônicas estão para as casas.” Uma única planta permite construir muitas casas — cada uma com sua cor e seus moradores. Guarde essa imagem: ela resume esta página inteira.

01 Por que Orientação a Objetos?

Até aqui, você resolveu problemas pensando em sequência, condição e repetição: um programa é uma lista de instruções que lê dados, decide o que fazer e repete tarefas. Isso é lógica de programação — e ela continua sendo usada dentro de cada método em Orientação a Objetos (OO). O que muda é a organização.

Em um programa puramente procedural, dados e funções ficam soltos: uma função lê uma lista de valores, outra função recebe essa mesma lista para calcular algo, outra a modifica. Conforme o sistema cresce, fica difícil lembrar quem pode mexer em quê — e um erro em uma função pode quebrar outras dez sem aviso.

A Orientação a Objetos propõe outra organização: em vez de espalhar dado e comportamento, você agrupa os dois na mesma unidade, chamada objeto. Um objeto Carro carrega seus próprios dados (cor, modelo) e as ações que fazem sentido para ele (ligar, desligar). Quem quiser usar um carro não precisa saber como ele funciona por dentro — só precisa saber chamar ligar().

Por que isso importa na prática

Um material citado nesta disciplina resume bem o motivo histórico da OO ganhar força: os três fatores que mais afetam o futuro do desenvolvimento de software seriam reutilização, reutilização e reutilização. Classes bem projetadas podem ser reaproveitadas em vários programas — assim como uma planta de casa pode ser usada para construir um bairro inteiro, não só uma casa.

Você não está abandonando o que aprendeu — está aprendendo onde guardar a lógica que já sabe escrever.

02 Classes e objetos

Pense em gatos e cães: ambos são animais, mas um mia e o outro late — semelhanças e diferenças que nos fazem naturalmente agrupar as coisas em categorias. É exatamente isso que uma classe faz em programação: descreve uma categoria de coisas que compartilham os mesmos tipos de dado e as mesmas ações possíveis.

Classe
O molde. Define quais atributos e métodos todo objeto desse tipo vai ter — mas não é, ela própria, um objeto usável.
Objeto
Uma instância concreta criada a partir de uma classe, com valores próprios para cada atributo. Também chamado de instância.

Repare no diagrama acima: a classe Casa é a planta — ela existe uma única vez e nunca é "habitada". Cada new Casa(...) constrói uma casa de verdade, com sua própria cor e seu próprio número de quartos. Mudar a cor de objCasa1 não afeta objCasa2 nem a planta original.

ClasseExemplos de objetos
Cachorrorex, bidu, totó
ContaBancariaconta123, conta456
Estudanteana, julio
Carrofusca, civic
Regra prática

Se a palavra é genérica e representa um "tipo de coisa" (carro, estudante, pedido, produto), ela tende a virar uma classe. Se é uma ocorrência específica desse tipo (o Fusca do seu tio, o estudante Julio), ela vira um objeto.

03 Anatomia de uma classe em Java

Toda classe em Java é declarada com a palavra-chave class, seguida do nome da classe e de um corpo delimitado por chaves { }. O modificador public aparece antes, indicando que a classe pode ser usada por qualquer outra classe do projeto.

Carro.java · estrutura mínima
public class Carro {
    // atributos e métodos entram aqui dentro
}

Nomes de classe seguem a convenção PascalCase (cada palavra começa com maiúscula, sem espaços ou hífens: ContaBancaria, ItemPedido) e podem conter letras, dígitos, _ e $ — mas nunca começar com um dígito.

Uma classe descreve três coisas ao mesmo tempo: um nome, um conjunto de atributos (o estado) e um conjunto de métodos (o comportamento). É assim que a UML costuma desenhar uma classe — em três compartimentos:

04 Atributos: o estado de um objeto

Atributos são variáveis declaradas dentro da classe, fora de qualquer método. Também são chamados de variáveis de instância, porque cada objeto criado a partir da classe guarda a sua própria cópia delas.

Carro.java · declarando atributos
public class Carro {
    private String modelo;
    private String cor;
    private boolean ligado;
}

Por convenção — e você vai entender o motivo na seção de encapsulamento — atributos quase sempre são declarados private. Isso significa que só código de dentro da própria classe pode enxergá-los diretamente.

Atributo ≠ variável local

Uma variável declarada dentro de um método (por exemplo, dentro de main) só existe enquanto aquele método está executando, e só aquele método a enxerga. Um atributo pertence ao objeto inteiro e existe durante toda a vida dele — qualquer método da classe pode usá-lo.

05 Métodos: o comportamento de um objeto

Métodos realizam tarefas e, quando fazem sentido, retornam um resultado. Toda declaração de método segue o mesmo esqueleto:

esqueleto de um métodomodificador tipoDeRetorno nomeDoMetodo(parâmetros) {
    instruções;
}
  • modificador — normalmente public ou private, define quem pode chamar o método;
  • tipo de retorno — o tipo do valor devolvido, ou void se o método não devolve nada;
  • nome — por convenção em camelCase, começando com minúscula (ligar, calcularMedia);
  • parâmetros — dados que o método precisa receber para trabalhar, entre parênteses e separados por vírgula; use () quando não precisar de nenhum.
Carro.java · dois métodos de comportamento
public void ligar() {
    this.ligado = true;
    System.out.println(modelo + " ligado. Vrum!");
}

public void desligar() {
    this.ligado = false;
    System.out.println(modelo + " desligado.");
}

Para chamar um método a partir de outra classe, você usa a variável que guarda o objeto, um ponto, e o nome do método: fusca.ligar();. Isso é bem diferente de chamar um método static (sem precisar de um objeto), que veremos na seção sobre main.

Parâmetro × argumento

Parâmetro é o nome usado na declaração do método (void setCor(String novaCor)). Argumento é o valor real passado na chamada (fusca.setCor("preto")). O mesmo método pode receber argumentos diferentes a cada chamada.

06 Instanciando objetos com new

A classe só ganha vida quando você cria um objeto a partir dela. Isso é feito com a expressão de criação de instância: a palavra-chave new seguida do nome da classe e parênteses — que, na verdade, chamam o construtor.

GaragemApp.java · criando dois objetos independentes
Carro fusca = new Carro("Fusca 1972", "azul");
Carro civic = new Carro("Civic 2024", "prata");

Cada chamada a new cria um objeto novo, guardado em memória, com sua própria cópia dos atributos. As variáveis fusca e civic são apenas rótulos que apontam para esses objetos — por isso, ligar o fusca não liga o civic, mesmo sendo os dois da mesma classe Carro.

Se o construtor não for declarado

Java fornece automaticamente um construtor padrão, sem parâmetros, que inicializa os atributos com valores neutros: 0 para números, false para boolean e null para objetos como String. Assim que você declarar qualquer construtor próprio, esse padrão deixa de existir automaticamente.

07 Encapsulamento: protegendo os dados

Em Orientação a Objetos, encapsular significa separar o programa em partes o mais isoladas possível, escondendo os detalhes internos de um objeto e expondo apenas o que é necessário para usá-lo. Na prática, em Java isso se traduz em uma regra simples: atributos privados, acesso controlado por métodos públicos.

Carro.java · getters e setters
public String getCor() {
    return cor;
}

public void setCor(String novaCor) {
    this.cor = novaCor;
}

Note a convenção de nomes: um método get devolve o valor de um atributo (getCor), um método set altera esse valor (setCor). Para atributos boolean, o padrão costuma ser isAlgumaCoisa() em vez de getAlgumaCoisa() — por exemplo, isLigado().

Por que não deixar tudo public e economizar código?

  • Validação: um setNota(double nota) pode recusar valores negativos antes de gravar — um atributo público não tem como impedir isso.
  • Liberdade para mudar por dentro: se amanhã você decidir guardar a cor como um código numérico em vez de texto, só o método getCor/setCor muda — quem usa a classe nem percebe.
  • Contrato claro: os métodos públicos dizem exatamente o que a classe promete fazer; o resto é detalhe de implementação.

Níveis de visibilidade em Java

ModificadorQuem enxerga
publicQualquer classe, de qualquer pacote do projeto.
protectedClasses do mesmo pacote, mais subclasses (mesmo em outros pacotes).
(nenhum modificador)Chamado de package-private: apenas classes do mesmo pacote.
privateSomente a própria classe onde foi declarado.

08 Construtores: preparando o objeto para nascer

O construtor é um método especial: tem o mesmo nome da classe, não declara nenhum tipo de retorno — nem void — e é executado automaticamente sempre que você usa new. Sua função é deixar o objeto pronto para uso já na criação.

Carro.java · construtor com parâmetros
public class Carro {
    private String modelo;
    private String cor;
    private boolean ligado;

    // construtor: recebe os valores iniciais do objeto
    public Carro(String modelo, String cor) {
        this.modelo = modelo;
        this.cor = cor;
        this.ligado = false; // todo carro nasce desligado
    }
}

Repare no this: dentro do construtor, o parâmetro e o atributo têm o mesmo nome (cor). this.cor se refere ao atributo do objeto; cor sozinho se refere ao parâmetro recebido. Sem o this, o Java não saberia distinguir os dois — e o atributo nunca seria realmente preenchido.

Pegadinha clássica

Escrever cor = cor; dentro do construtor não faz nada de útil: é o parâmetro recebendo a si mesmo. O correto é sempre this.cor = cor; quando os nomes coincidem.

Um construtor pode ter mais de uma versão

Assim como métodos, construtores podem ser sobrecarregados (mesma classe, assinaturas diferentes). Por exemplo, você poderia adicionar um segundo construtor que já recebe se o carro nasce ligado:

Carro.java · construtor sobrecarregado (opcional)
public Carro(String modelo, String cor, boolean ligado) {
    this.modelo = modelo;
    this.cor = cor;
    this.ligado = ligado;
}

Java escolhe automaticamente qual construtor chamar de acordo com a quantidade e o tipo dos argumentos passados em new Carro(...).

09 O método main: onde tudo começa

Todo programa Java precisa de um ponto de partida — o método pelo qual a JVM (a máquina virtual que executa Java) começa a rodar o código. Esse ponto é sempre:

assinatura fixa do método mainpublic static void main(String[] args) { ... }

Cada palavra dessa assinatura importa:

  • public — a JVM, que é externa ao seu programa, precisa conseguir chamá-lo;
  • static — o método pertence à classe, não a um objeto específico; por isso pode rodar sem que nada tenha sido instanciado ainda;
  • void — não devolve valor algum para quem o chamou (a JVM);
  • String[] args — argumentos que podem ser passados na linha de comando ao executar o programa.
static × de instância

Um método de instância (como ligar()) só existe "dentro" de um objeto — por isso você escreve fusca.ligar(). Um método static pertence à classe inteira e é chamado direto pelo nome dela, como NomeDaClasse.metodoEstatico(). É justamente por ser static que o main pode rodar antes de qualquer new acontecer — ele é o ponto de partida que vai criar os primeiros objetos.

10 Exemplo completo, do zero ao console

Juntando tudo que vimos até aqui: uma classe Carro completa e uma classe com main que cria dois carros, liga um deles e troca a cor do outro.

Carro.java · classe completa
public class Carro {

    // atributos: o estado de cada carro
    private String modelo;
    private String cor;
    private boolean ligado;

    // construtor: prepara o carro assim que ele "nasce"
    public Carro(String modelo, String cor) {
        this.modelo = modelo;
        this.cor = cor;
        this.ligado = false;
    }

    // métodos: o comportamento de cada carro
    public void ligar() {
        this.ligado = true;
        System.out.println(modelo + " ligado. Vrum!");
    }

    public void desligar() {
        this.ligado = false;
        System.out.println(modelo + " desligado.");
    }

    // get/set: acesso controlado ao estado privado
    public boolean isLigado() {
        return ligado;
    }

    public String getModelo() {
        return modelo;
    }

    public String getCor() {
        return cor;
    }

    public void setCor(String novaCor) {
        this.cor = novaCor;
    }
}
GaragemApp.java · classe com o método main
public class GaragemApp {

    public static void main(String[] args) {
        // cada "new" cria um objeto independente, a partir da mesma classe
        Carro fusca = new Carro("Fusca 1972", "azul");
        Carro civic = new Carro("Civic 2024", "prata");

        fusca.ligar();
        civic.setCor("preto");

        System.out.println(fusca.getModelo() + " está ligado: " + fusca.isLigado());
        System.out.println(civic.getModelo() + " agora é " + civic.getCor());
    }
}
saída no consoleFusca 1972 ligado. Vrum!
Fusca 1972 está ligado: true
Civic 2024 agora é preto

Repare que GaragemApp nunca acessa fusca.ligado ou civic.cor diretamente — tudo passa pelos métodos públicos que a classe Carro decidiu expor. Esse é o encapsulamento funcionando na prática, não apenas na teoria.

11 Desafio prático: classe Estudante

Hora de aplicar sozinho. O objetivo é o mesmo de uma atividade clássica desta disciplina — mas agora você já tem todo o vocabulário para resolver com confiança.

Enunciado

Crie uma classe Estudante cujos objetos guardem:

  • ra (matrícula, int)
  • nome (String)
  • nota1, nota2, nota3 (double)

Todos os atributos devem ser private, inicializados por um construtor. Crie também um método calcularMedia() que devolva a média das três notas.

Em uma classe separada com main, instancie três estudantes e exiba, para cada um, uma linha no formato "O estudante Ana possui média 8.17".

Roteiro sugerido

  1. Declare os cinco atributos private em Estudante.
  2. Escreva o construtor recebendo os cinco valores e usando this para atribuí-los.
  3. Escreva calcularMedia(), retornando (nota1 + nota2 + nota3) / 3.
  4. Escreva getNome() e getRa() para poder exibir esses dados fora da classe.
  5. Na classe com main, crie os três objetos com new e use System.out.printf para formatar a saída com duas casas decimais (%.2f).
Desafio bônus

Depois de terminar, tente adicionar um método foiAprovado() que devolva true quando a média for maior ou igual a 6.0. Pense: esse método precisa de algum parâmetro, ou ele já tem tudo que precisa dentro do próprio objeto?

Ver solução comentada
Estudante.java · solução sugerida
public class Estudante {
    private int ra;
    private String nome;
    private double nota1, nota2, nota3;

    public Estudante(int ra, String nome,
                     double nota1, double nota2, double nota3) {
        this.ra = ra;
        this.nome = nome;
        this.nota1 = nota1;
        this.nota2 = nota2;
        this.nota3 = nota3;
    }

    public double calcularMedia() {
        return (nota1 + nota2 + nota3) / 3;
    }

    public boolean foiAprovado() {
        return calcularMedia() >= 6.0;
    }

    public String getNome() { return nome; }
    public int getRa() { return ra; }
}
EscolaApp.java · testando a classe com três estudantes
public class EscolaApp {
    public static void main(String[] args) {
        Estudante[] turma = {
            new Estudante(1, "Ana", 8.5, 9.0, 7.0),
            new Estudante(2, "Julio", 5.0, 6.5, 8.0),
            new Estudante(3, "Bia", 4.0, 6.0, 5.5)
        };

        for (Estudante e : turma) {
            System.out.printf("O estudante %s possui média %.2f%n",
                e.getNome(), e.calcularMedia());
        }
    }
}
saída no consoleO estudante Ana possui média 8.17
O estudante Julio possui média 6.50
O estudante Bia possui média 5.17
Vírgula ou ponto?

O printf usa o idioma do sistema. Num computador configurado em português, a saída pode aparecer como 8,17. Para forçar o ponto, use System.out.printf(Locale.US, …).

12 Erros comuns de quem está começando

SintomaCausa provável
O atributo fica null ou com valor errado depois do construtorEsqueceu o this. quando o parâmetro tem o mesmo nome do atributo — cor = cor; não atribui nada útil.
Qualquer classe consegue alterar os dados do objeto sem restriçãoAtributo declarado public em vez de private, perdendo o encapsulamento.
NullPointerException ao chamar um métodoTentou chamar objeto.metodo() sem antes ter feito new para criar o objeto.
"Não sei em qual método uma variável está disponível"Confusão entre atributo (pertence ao objeto todo) e variável local (só existe dentro de um método).
O programa inteiro está dentro do mainNenhuma divisão em classes — perde exatamente a organização que a OO oferece.
Erro de compilação em nomes de classe ou métodoQuebra de convenção: classe começando com minúscula, ou método em PascalCase em vez de camelCase.

E depois?

Com classes, objetos, atributos, métodos, construtores e encapsulamento consolidados, você já tem a base necessária para os próximos temas da disciplina: herança (uma classe reaproveitando características de outra), polimorfismo (um mesmo método se comportando de formas diferentes conforme a classe), interfaces e o cuidado com dependências entre classes. Todos esses conceitos são construídos em cima do que você revisou aqui — vale a pena garantir que classe, objeto, atributo, método, construtor e encapsulamento estejam bem firmes antes de avançar.

14 Resumo e autoteste

Glossário rápido para revisar antes de uma prova ou antes de continuar os estudos:

Classe
Molde que define atributos e métodos de um tipo de objeto.
Objeto
Instância concreta de uma classe, criada com new, com estado próprio.
Atributo
Variável declarada na classe; guarda o estado de cada objeto.
Método
Bloco de código que define um comportamento do objeto (ou da classe, se static).
Construtor
Método especial, sem retorno e com o nome da classe, executado ao criar um objeto com new.
Encapsulamento
Esconder o estado interno (private) e expor acesso controlado por métodos públicos (get/set).
this
Referência ao próprio objeto; usada para diferenciar atributo de parâmetro com o mesmo nome.
static
Pertence à classe, não a um objeto específico — como o método main.

Teste rápido

1. Qual a diferença entre classe e objeto?

Classe é o molde/planta; objeto é uma instância concreta criada a partir da classe, com valores próprios para seus atributos.

2. Por que usar this.cor = cor; em vez de só cor = cor; no construtor?

Porque parâmetro e atributo têm o mesmo nome. this.cor aponta para o atributo do objeto; sem o this, Java entenderia as duas referências como o próprio parâmetro, e o atributo nunca seria preenchido.

3. Por que atributos costumam ser private?

Para permitir validação de dados, liberdade de mudar a implementação interna sem afetar quem usa a classe, e deixar claro qual é o "contrato público" da classe.

4. O método main é static. Por que isso é necessário?

Porque a JVM precisa executar esse método antes que qualquer objeto tenha sido criado. Métodos static pertencem à classe, não a uma instância, então podem rodar sem new.

5. Dois carros foram criados a partir da mesma classe Carro. Ligar um deles liga o outro também?

Não. Cada objeto tem sua própria cópia dos atributos (variáveis de instância) — alterar o estado de um objeto nunca afeta outro objeto, mesmo que sejam da mesma classe.
