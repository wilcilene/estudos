Gatilhos (Triggers)

Procedimentos armazenados são executados quando alguém os chama explicitamente com CALL. Mas e se eu quiser que algo aconteça automaticamente, sempre que uma linha for inserida, alterada ou apagada — sem que ninguém precise lembrar de chamar nada? É para isso que existem os gatilhos. Vamos entrar no sistema de vigilância automática de uma nave-mãe alienígena.

O que vocês vão aprender aqui

  • Entender o que é um trigger e quando ele dispara.
  • Diferenciar BEFORE e AFTER, e INSERT/UPDATE/DELETE.
  • Usar OLD e NEW para acessar os valores da linha afetada.
  • Criar um trigger de auditoria e um trigger de validação complexa.

1. A nave-mãe e seu registro de tripulantes

🛸 Nave-mãe Zorvex

A nave-mãe mantém um registro de todos os tripulantes alienígenas e seus níveis de autorização. Toda alteração nesse registro precisa ser automaticamente auditada — a central de comando exige saber quem mudou o quê e quando, sem depender de a aplicação lembrar de registrar isso.

CREATE TABLE tripulante (
  id_tripulante INT PRIMARY KEY AUTO_INCREMENT,
  nome_tripulante VARCHAR(80) NOT NULL,
  nivel_autorizacao INT NOT NULL DEFAULT 1
);

CREATE TABLE auditoria_tripulante (
  id_auditoria INT PRIMARY KEY AUTO_INCREMENT,
  id_tripulante INT NOT NULL,
  nivel_anterior INT,
  nivel_novo INT,
  data_alteracao DATETIME
);

2. Criando um trigger de auditoria (AFTER UPDATE)

Eu quero que, toda vez que o nível de autorização de um tripulante mudar, uma linha seja automaticamente registrada em auditoria_tripulante — sem que a aplicação precise fazer isso manualmente:

DELIMITER //

CREATE TRIGGER trg_auditoria_autorizacao
AFTER UPDATE ON tripulante
FOR EACH ROW
BEGIN
  IF OLD.nivel_autorizacao <> NEW.nivel_autorizacao THEN
    INSERT INTO auditoria_tripulante (id_tripulante, nivel_anterior, nivel_novo, data_alteracao)
    VALUES (OLD.id_tripulante, OLD.nivel_autorizacao, NEW.nivel_autorizacao, NOW());
  END IF;
END //

DELIMITER ;
Linha a linha: o trigger de auditoria
TrechoO que significa
CREATE TRIGGER trg_auditoria_autorizacao Declara um gatilho com esse nome — ele não é chamado manualmente, apenas disparado pelo SGBD quando o evento ocorrer.
AFTER UPDATE ON tripulante Define o evento que dispara o trigger: depois que um UPDATE na tabela tripulante for concluído.
FOR EACH ROW O gatilho executa uma vez para cada linha afetada pelo UPDATE, não uma vez só para o comando inteiro.
OLD.nivel_autorizacao OLD representa a linha como ela estava antes da alteração — só existe em UPDATE e DELETE.
NEW.nivel_autorizacao NEW representa a linha como ela fica depois da alteração — só existe em INSERT e UPDATE.
IF OLD... <> NEW... THEN Só registra auditoria se o nível realmente mudou — evita gravar linhas de auditoria para updates que não alteraram esse campo.

Depois de criado, o trigger age sozinho. Se alguém rodar:

UPDATE tripulante SET nivel_autorizacao = 5 WHERE id_tripulante = 3;

...uma linha é automaticamente inserida em auditoria_tripulante, sem que ninguém tenha escrito esse INSERT explicitamente. A auditoria passa a ser garantida pelo banco, não pela boa vontade de quem programa a aplicação.

Conceito: por que AFTER e não BEFORE, aqui?

Usamos AFTER UPDATE porque só queremos registrar a auditoria depois que temos certeza de que a alteração foi aceita pelo banco. Um trigger BEFORE dispara antes da alteração ser efetivada — é o momento certo para validar ou ajustar os dados, não para registrar um fato que ainda pode não se confirmar.

3. Trigger de validação complexa (BEFORE INSERT)

Agora um caso diferente: a central de comando exige que nenhum tripulante novo entre com nível de autorização acima de 3, a não ser que seja da espécie "Comandante". Essa é uma regra que um simples CHECK de coluna não resolve, porque depende de outra coluna da mesma linha:

DELIMITER //

CREATE TRIGGER trg_valida_autorizacao
BEFORE INSERT ON tripulante
FOR EACH ROW
BEGIN
  IF NEW.nivel_autorizacao > 3 AND NEW.nome_tripulante NOT LIKE 'Comandante%' THEN
    SIGNAL SQLSTATE '45000'
      SET MESSAGE_TEXT = 'Apenas Comandantes podem ter nível de autorização acima de 3.';
  END IF;
END //

DELIMITER ;
Linha a linha: o trigger de validação
TrechoO que significa
BEFORE INSERT ON tripulante Dispara antes da linha ser efetivamente inserida — é a hora certa para bloquear a inserção, se necessário.
IF NEW.nivel_autorizacao > 3 AND ... Verifica a condição combinando duas colunas da mesma linha nova — algo que uma restrição CHECK simples em uma coluna isolada não conseguiria expressar com a mesma clareza.
SIGNAL SQLSTATE '45000' ... Lança um erro customizado, cancelando o INSERT inteiro e devolvendo a mensagem definida para quem tentou inserir a linha.

Se alguém tentar inserir um tripulante comum com nível 5, o banco recusa a operação antes mesmo de gravar a linha:

INSERT INTO tripulante (nome_tripulante, nivel_autorizacao) VALUES ('Zyx', 5);
-- Erro: Apenas Comandantes podem ter nível de autorização acima de 3.

4. Os seis momentos possíveis de um trigger

Combinações de BEFORE/AFTER com INSERT/UPDATE/DELETE
MomentoEventoUso típico
BEFOREINSERTValidar ou ajustar valores antes de gravar uma linha nova.
AFTERINSERTDisparar efeitos colaterais depois que a linha já foi gravada (ex: notificar, auditar).
BEFOREUPDATEValidar a alteração antes que ela seja aplicada.
AFTERUPDATERegistrar auditoria da alteração já confirmada.
BEFOREDELETEImpedir ou registrar o estado de uma linha antes que ela seja removida.
AFTERDELETEAtualizar dados relacionados depois que a linha já foi removida.

⚠️ Cuidado com triggers em cadeia

Um trigger pode disparar um UPDATE em outra tabela, que por sua vez tem seu próprio trigger, que altera outra tabela... Isso pode criar cadeias difíceis de acompanhar e depurar. Usem triggers para regras claras e bem delimitadas — não para esconder fluxos de negócio inteiros que a equipe precisará entender depois.

🤔 Confira se entendeu

Por que o trigger de validação usa BEFORE INSERT, e não AFTER INSERT?

Porque BEFORE dispara antes da linha ser gravada, permitindo cancelar a inserção com SIGNAL se a regra for violada. Se fosse AFTER, a linha inválida já teria sido gravada antes do trigger rodar.

No trigger de auditoria, por que só OLD está disponível em um DELETE, e não NEW?

Porque NEW representa a linha depois da alteração — em um DELETE não existe "depois", a linha deixa de existir. Por isso DELETE só tem acesso a OLD, o estado da linha antes de ser removida.
