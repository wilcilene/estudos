DDL e DML no MySQL: a Pizzaria Miau 🍕🐈

Nesta atividade você vai construir, passo a passo, o banco de dados de uma pizzaria criada especialmente para gatos. A ideia é simples: primeiro montamos a estrutura que guardará as informações; depois começamos a cadastrar, alterar e remover os dados dessa estrutura.

Antes de começar: DDL ou DML?

Comando Grupo O que faz? Exemplo na Pizzaria Miau
CREATE DDL Cria estruturas no banco de dados. Criar o banco e a tabela de pizzas.
ALTER DDL Altera a estrutura de uma tabela existente. Adicionar a coluna nivel_catnip.
DROP DDL Remove uma estrutura inteira. Excluir completamente a tabela de pizzas.
INSERT DML Adiciona registros. Cadastrar sabores no cardápio.
UPDATE DML Altera registros existentes. Aumentar o preço da pizza de atum.
DELETE DML Remove registros, mantendo a tabela. Tirar do cardápio um sabor rejeitado pelos gatos.

Regra para lembrar

DDL muda a estrutura onde os dados serão armazenados.

DML trabalha com os dados que já estão dentro dessa estrutura.

0. Prepare seu ambiente

Você pode executar os comandos desta aula no MySQL Workbench, no terminal do MySQL, no phpMyAdmin ou em outro cliente compatível com MySQL. Execute os blocos na ordem apresentada.

Como acompanhar a atividade

A cada etapa:

  1. Leia o objetivo.
  2. Copie o comando SQL.
  3. Execute no MySQL.
  4. Observe o resultado.
  5. Leia a explicação do que mudou.

1. Criando o banco da Pizzaria Miau

Nossa pizzaria é voltada para gatos extremamente exigentes: atum é sucesso, frango costuma ser aceito, peixe ganha pontos extras e qualquer receita muito extravagante corre o risco de receber aquele olhar felino de desaprovação.

Objetivo

Criar um banco chamado pizzaria_miau e informar ao MySQL que trabalharemos nele.

CREATE DATABASE pizzaria_miau;

USE pizzaria_miau;
Trecho O que está acontecendo?
CREATE DATABASE pizzaria_miau; Cria o banco de dados. Estamos definindo uma nova estrutura, portanto é DDL.
USE pizzaria_miau; Seleciona o banco que receberá os próximos comandos.

2. Criando a estrutura para cadastrar as pizzas

Agora vamos criar a tabela que armazenará o cardápio. Neste momento não existe nenhuma pizza cadastrada. Estamos somente definindo quais informações cada pizza poderá ter. 

CREATE TABLE pizzas (
    id INT AUTO_INCREMENT PRIMARY KEY,
    nome VARCHAR(100) NOT NULL,
    proteina_principal VARCHAR(50) NOT NULL,
    preco DECIMAL(6,2) NOT NULL,
    favorita_dos_gatos BOOLEAN DEFAULT FALSE
);
Trecho O que significa?
id INT AUTO_INCREMENT PRIMARY KEY Cada pizza recebe um número único automaticamente.
nome VARCHAR(100) NOT NULL Guarda o nome da pizza. NOT NULL impede o cadastro sem nome.
proteina_principal VARCHAR(50) Informa o ingrediente principal: atum, sardinha, frango etc.
preco DECIMAL(6,2) Guarda valores monetários com duas casas decimais.
favorita_dos_gatos BOOLEAN Marca se o sabor foi aprovado pelo comitê felino.

O que mudou?

Antes não existia tabela. Agora existe uma estrutura chamada pizzas com cinco colunas. Como criamos a estrutura, usamos DDL.

Confira a estrutura criada

DESCRIBE pizzas;

Observe os nomes das colunas, os tipos de dados e quais campos aceitam ou não valores nulos.

3. Cadastrando o primeiro cardápio felino

A estrutura está pronta. Agora começamos a trabalhar com os dados. Para isso usamos INSERT. 

INSERT INTO pizzas (nome, proteina_principal, preco, favorita_dos_gatos)
VALUES
    ('Atum Supremo', 'Atum', 29.90, TRUE),
    ('Sardinha Crocante', 'Sardinha', 27.50, TRUE),
    ('Frango Ronronante', 'Frango', 25.90, TRUE),
    ('Salmão do Sofá', 'Salmão', 34.90, TRUE),
    ('Brócolis Misterioso', 'Brócolis', 22.00, FALSE);

Por que existe uma pizza de brócolis?

Porque alguém da administração decidiu que “os gatos precisam experimentar coisas novas”. O banco de dados registra a decisão. O olhar de julgamento dos gatos fica por conta deles.

Veja o que foi cadastrado

SELECT * FROM pizzas;

DDL ou DML?

INSERT não criou nem alterou colunas. Ele apenas colocou registros dentro da estrutura existente. Portanto é DML.

4. Aumentando o preço da pizza de atum

A Atum Supremo virou a campeã de pedidos. Naturalmente, a administração da Pizzaria Miau percebeu a oportunidade. 

UPDATE pizzas
SET preco = 32.90
WHERE id = 1;

Confira apenas a pizza alterada

SELECT *
FROM pizzas
WHERE id = 1;

O que mudou?

A tabela continua com as mesmas colunas. Apenas o valor de um registro foi alterado. Isso é DML.

Atenção ao WHERE ⚠️

Veja este comando:

UPDATE pizzas
SET preco = 32.90;

Sem WHERE, todas as pizzas receberiam o mesmo preço. Não execute esse comando agora. Ele está aqui para mostrar por que o filtro é tão importante.

5. A estrutura precisa de uma informação nova

A pizzaria descobriu que alguns sabores ficam mais populares quando recebem catnip. Precisamos armazenar essa informação, mas a tabela ainda não possui uma coluna para isso.

Pense antes de executar

Para guardar uma informação que ainda não cabe na estrutura, precisamos mudar a tabela. Portanto voltamos à DDL. 

ALTER TABLE pizzas
ADD nivel_catnip VARCHAR(20) DEFAULT 'Sem catnip';

Confira novamente a estrutura

DESCRIBE pizzas;

Agora a tabela possui uma nova coluna chamada nivel_catnip.

Antes do ALTER Depois do ALTER
id id
nome nome
proteina_principal proteina_principal
preco preco
favorita_dos_gatos favorita_dos_gatos

6. Preenchendo a nova coluna

A coluna já existe. Agora vamos colocar dados nela. Observe a mudança de raciocínio: ALTER criou a coluna; UPDATE preenche os registros. 

UPDATE pizzas
SET nivel_catnip = 'Extra'
WHERE nome = 'Atum Supremo';

UPDATE pizzas
SET nivel_catnip = 'Moderado'
WHERE nome = 'Salmão do Sofá';
SELECT nome, nivel_catnip
FROM pizzas;

Compare

ALTER TABLE mudou a estrutura → DDL.

UPDATE mudou os dados dentro dela → DML.

7. O fracasso do Brócolis Misterioso

Após uma semana no cardápio, nenhum gato pediu a pizza Brócolis Misterioso. Um deles cheirou, encarou o atendente e foi embora. A pizzaria decidiu remover esse sabor. 

DELETE FROM pizzas
WHERE nome = 'Brócolis Misterioso';

Confira o cardápio

SELECT * FROM pizzas;

DELETE não apaga a tabela

O registro foi removido, mas a tabela pizzas continua existindo, com suas colunas e os demais sabores. Portanto DELETE é DML.

8. DELETE x DROP: a diferença que você precisa enxergar

Comando Resultado A tabela ainda existe? Grupo
DELETE FROM pizzas; Remove todos os registros. Sim. DML
DROP TABLE pizzas; Remove a própria tabela. Não. DDL

Não execute ainda 🐾

O comando abaixo apagaria completamente a tabela que acabamos de construir. Vamos deixá-lo apenas como exemplo por enquanto: 

DROP TABLE pizzas;

9. Sua vez: desafio do gerente felino

Execute os desafios abaixo sem copiar uma solução pronta. Depois compare seu raciocínio com as dicas.

Desafio 1 — novo sabor

Cadastre a pizza Patê Imperial, com proteína principal Patê, preço 31.50 e marque-a como favorita.

Mostrar dica

Você não precisa mudar a estrutura. O comando começa com INSERT INTO.

Desafio 2 — promoção relâmpago

Altere o preço da Sardinha Crocante para 24.90.

Mostrar dica

Você está alterando um dado existente. Use UPDATE com WHERE.

Desafio 3 — nova informação

A pizzaria quer informar se a pizza pode ser servida gelada. Crie uma coluna chamada pode_servir_gelada do tipo BOOLEAN.

Mostrar dica

Agora a estrutura precisa mudar. Use ALTER TABLE ... ADD ....

Desafio 4 — veto do conselho dos gatos

Remova do cardápio a pizza Frango Ronronante, mas mantenha a tabela.

Mostrar dica

Você quer remover um registro, não a estrutura. Use DELETE com WHERE.

10. Resumo final

DDL — Data Definition Language
Comandos que definem ou alteram estruturas do banco. Nesta aula: CREATE, ALTER e DROP.
DML — Data Manipulation Language
Comandos que inserem, alteram ou removem dados. Nesta aula: INSERT, UPDATE e DELETE.
Estrutura
Banco, tabelas, colunas, tipos de dados e demais definições que determinam como os dados serão organizados.
Registro
Uma linha armazenada em uma tabela. Na Pizzaria Miau, cada registro representa uma pizza do cardápio.

Teste rápido

Se você lembrar apenas de uma coisa, lembre desta pergunta:

“Estou mudando a estrutura ou os dados que estão dentro dela?”

Estrutura → DDL. Dados → DML.

11. Quer repetir a atividade do zero?

Depois de terminar os exercícios, você pode apagar todo o banco da atividade e começar novamente:

DROP DATABASE pizzaria_miau;

Por que isso é DDL?

Porque o comando remove uma estrutura inteira do banco de dados. Use somente quando quiser realmente apagar toda a atividade.

Fim da atividade. Agora você já consegue diferenciar DDL de DML observando o efeito real de cada comando no banco de dados.
