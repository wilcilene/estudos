Linguagens SQL

JOINs, subconsultas e agregação

Até agora cada consulta mexia em uma tabela por vez. Mas a graça de ter várias tabelas relacionadas é justamente combiná-las. Vamos praticar com um torneio de e-sports disputado inteiramente por equipes de robôs.

O que vocês vão aprender aqui

  • Combinar tabelas com INNER JOIN e LEFT JOIN.
  • Entender por que o MySQL não tem FULL JOIN nativo e como contornar isso.
  • Resumir dados com funções de agregação, GROUP BY e HAVING.
  • Escrever uma subconsulta dentro do WHERE.

1. O cenário: o torneio

🎮 Liga Robótica de E-sports

Três tabelas organizam o torneio: equipe (as equipes inscritas), robo_jogador (cada robô pertence a uma equipe) e partida (os confrontos, com o placar de cada lado).

CREATE TABLE equipe (
  id_equipe INT PRIMARY KEY AUTO_INCREMENT,
  nome_equipe VARCHAR(60) NOT NULL UNIQUE
);

CREATE TABLE robo_jogador (
  id_robo INT PRIMARY KEY AUTO_INCREMENT,
  nome VARCHAR(60) NOT NULL,
  id_equipe INT NOT NULL,
  pontuacao_media DECIMAL(5,2) NOT NULL DEFAULT 0,
  FOREIGN KEY (id_equipe) REFERENCES equipe(id_equipe)
);

CREATE TABLE partida (
  id_partida INT PRIMARY KEY AUTO_INCREMENT,
  id_equipe_casa INT NOT NULL,
  id_equipe_visitante INT NOT NULL,
  placar_casa INT NOT NULL,
  placar_visitante INT NOT NULL,
  data_partida DATE NOT NULL,
  FOREIGN KEY (id_equipe_casa) REFERENCES equipe(id_equipe),
  FOREIGN KEY (id_equipe_visitante) REFERENCES equipe(id_equipe)
);

2. INNER JOIN: só o que casa dos dois lados

Queremos o nome de cada robô junto com o nome da equipe dele — uma informação que, sozinha, nenhuma das duas tabelas tem completa.

SELECT r.nome AS robo, e.nome_equipe AS equipe
FROM robo_jogador AS r
INNER JOIN equipe AS e ON r.id_equipe = e.id_equipe
ORDER BY e.nome_equipe;
Linha a linha: robôs e suas equipes
TrechoO que significa
SELECT r.nome AS robo, e.nome_equipe AS equipe Escolhe colunas de duas tabelas diferentes, usando apelidos (r e e) para indicar de qual tabela cada coluna vem, e AS para renomear o resultado.
FROM robo_jogador AS r Define robo_jogador como ponto de partida da consulta, apelidada de r.
INNER JOIN equipe AS e Diz que vamos combinar com a tabela equipe, apelidada de e.
ON r.id_equipe = e.id_equipe A regra de combinação: só junta uma linha de robo_jogador com a linha de equipe em que o id_equipe é igual. Esse é exatamente o papel da chave estrangeira.

Conceito: por que "inner"?

INNER JOIN só mantém no resultado as linhas em que a condição do ON encontra correspondência nos dois lados. Se um robô, por engano, tivesse um id_equipe que não existe em equipe — o que a própria FOREIGN KEY impede, a propósito — ele simplesmente não apareceria no resultado.

3. LEFT JOIN: mantendo quem não tem correspondência

Uma equipe acabou de se inscrever e ainda não cadastrou nenhum robô. Com INNER JOIN, ela nem apareceria na consulta anterior. Para listar todas as equipes, com ou sem robôs, usamos LEFT JOIN:

SELECT e.nome_equipe, r.nome AS robo
FROM equipe AS e
LEFT JOIN robo_jogador AS r ON r.id_equipe = e.id_equipe;

Aqui a tabela à esquerda do LEFT JOIN é equipe: todas as suas linhas aparecem no resultado, mesmo quando não há robô correspondente — nesse caso, a coluna robo simplesmente vem como NULL.

INNER × LEFT × RIGHT × FULL JOIN
TipoO que mantém no resultado
INNER JOINSó as linhas que têm correspondência nos dois lados.
LEFT JOINTodas as linhas da tabela à esquerda, com ou sem correspondência à direita.
RIGHT JOINTodas as linhas da tabela à direita, com ou sem correspondência à esquerda.
FULL JOINTodas as linhas dos dois lados, correspondendo ou não.

⚠️ O MySQL não tem FULL JOIN

Diferente do PostgreSQL e do SQL Server, o MySQL não implementa FULL JOIN diretamente. Quando vocês precisarem desse comportamento no MySQL, o caminho é combinar um LEFT JOIN com um RIGHT JOIN usando UNION. Na prática, costuma ser mais simples reescrever a pergunta usando dois LEFT JOINs separados.

4. Resumindo dados com funções de agregação

Quantos robôs cada equipe tem, e qual a pontuação média deles?

SELECT e.nome_equipe,
       COUNT(r.id_robo) AS total_robos,
       AVG(r.pontuacao_media) AS media_equipe
FROM equipe AS e
LEFT JOIN robo_jogador AS r ON r.id_equipe = e.id_equipe
GROUP BY e.id_equipe, e.nome_equipe
HAVING COUNT(r.id_robo) >= 2
ORDER BY media_equipe DESC;
Linha a linha: ranking de equipes com 2+ robôs
TrechoO que significa
COUNT(r.id_robo) AS total_robos Conta quantas linhas de robo_jogador casaram com cada equipe no JOIN.
AVG(r.pontuacao_media) AS media_equipe Calcula a média da pontuação dos robôs daquela equipe.
GROUP BY e.id_equipe, e.nome_equipe Agrupa as linhas por equipe antes de aplicar COUNT e AVG — sem isso, o resultado seria uma única média para o torneio inteiro.
HAVING COUNT(r.id_robo) >= 2 Filtra os grupos já calculados, mantendo só equipes com 2 ou mais robôs. Não dá para usar WHERE aqui, porque WHERE filtra linhas antes do agrupamento, e COUNT(...) só existe depois dele.

Conceito: WHERE × HAVING

WHERE filtra linhas individuais, antes de qualquer agrupamento. HAVING filtra grupos inteiros, depois que GROUP BY e as funções de agregação já foram calculados. Uma regra prática: se a condição usa COUNT, SUM, AVG, MIN ou MAX, ela vai no HAVING; qualquer outra condição vai no WHERE.

5. Subconsultas: uma consulta dentro da outra

Quais robôs têm pontuação acima da média geral do torneio?

SELECT nome, pontuacao_media
FROM robo_jogador
WHERE pontuacao_media > (
  SELECT AVG(pontuacao_media) FROM robo_jogador
);

A consulta entre parênteses roda primeiro e devolve um único número (a média geral); depois, a consulta externa usa esse número para filtrar os robôs. Isso é uma subconsulta escalar — ela devolve exatamente um valor, por isso pode ser comparada diretamente com >.

🤔 Confira se entendeu

Por que a consulta de equipes com LEFT JOIN mostra uma linha com robô = NULL para a equipe recém-inscrita?

Porque o LEFT JOIN mantém todas as linhas da tabela à esquerda (equipe) mesmo quando não existe robô correspondente em robo_jogador; nesses casos, as colunas vindas da tabela à direita aparecem como NULL.

Por que não podemos escrever WHERE COUNT(r.id_robo) >= 2 em vez de usar HAVING?

Porque WHERE é avaliado antes do agrupamento (GROUP BY), e COUNT() só existe depois que os grupos foram formados. Por isso essa condição precisa ir no HAVING.
