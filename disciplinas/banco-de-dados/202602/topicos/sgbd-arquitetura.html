SGBD

Arquitetura e funcionamento de um SGBD

Até aqui, vocês modelaram dados no papel. A partir de agora, esses dados vão morar em um banco de verdade — e quem cuida deles é o SGBD. Para entender por que ele é tão mais do que "um lugar para guardar tabelas", eu gosto de comparar um SGBD com a torre de controle de uma estação espacial.

O que vocês vão aprender aqui

  • Definir o que é um SGBD e por que ele fica entre a aplicação e os dados.
  • Listar as principais funções de um SGBD.
  • Reconhecer os componentes internos de um SGBD e o papel de cada um.
  • Comparar PostgreSQL, MySQL, Oracle e SQLite e saber quando cada um faz sentido.

1. A torre de controle da estação

🛰️ A analogia

Imaginem uma estação espacial onde dezenas de módulos — laboratórios, docas, naves de carga — precisam ler e gravar informações no mesmo arquivo central de registros, ao mesmo tempo, sem que um módulo apague por acidente o que outro acabou de escrever, e sem que a estação perca tudo se a energia cair por um segundo. Ninguém deixaria cada módulo escrever diretamente no arquivo por conta própria — existe uma torre de controle no meio, que recebe cada pedido, decide a ordem, aplica as regras e só então grava ou devolve a resposta. O SGBD é essa torre de controle para os seus dados.

Formalmente: um Sistema Gerenciador de Banco de Dados (SGBD) é o software que fica entre as aplicações e os arquivos físicos de dados, oferecendo uma forma controlada, consistente e segura de criar, ler, alterar e remover informações — sem que cada aplicação precise reinventar como os dados são armazenados em disco.

2. As funções que a torre de controle precisa cumprir

Funções essenciais de um SGBD
Função O que ela garante
Definição de dados Permite descrever a estrutura (tabelas, colunas, tipos, chaves) através da DDL, que vocês vão estudar no próximo bloco de tópicos.
Manipulação de dados Permite inserir, consultar, atualizar e remover registros através da DML e da DQL.
Controle de concorrência Coordena vários módulos (usuários) acessando os mesmos dados ao mesmo tempo, sem que um pedido corrompa o resultado do outro.
Controle de integridade Aplica as regras definidas na modelagem (chaves primárias, estrangeiras, restrições) automaticamente, mesmo que a aplicação esqueça de validar algo.
Segurança e controle de acesso Decide quem pode ver ou alterar cada parte dos dados, por meio de usuários, perfis e permissões.
Recuperação de falhas Garante que, mesmo se a energia cair no meio de uma operação, os dados voltem a um estado consistente quando o sistema religar.

3. Por dentro da torre: os componentes

Quando um módulo da estação envia um pedido — por exemplo, um SELECT — ele passa por várias "salas" dentro da torre de controle antes de uma resposta voltar:

O que cada componente faz
Componente Função
Processador de consultas Recebe o SQL enviado pela aplicação, verifica a sintaxe e traduz o comando para uma representação interna.
Otimizador Decide o caminho de execução mais eficiente para aquela consulta (qual índice usar, em que ordem juntar as tabelas).
Gerenciador de transações Garante que operações agrupadas em uma transação sejam tratadas como um bloco único — é o tema da próxima parte da disciplina.
Gerenciador de armazenamento e buffer Controla como os dados são lidos e escritos em disco, mantendo cópias recentes em memória para acelerar o acesso.
Catálogo de dados (dicionário de dados) Guarda os "metadados": quais tabelas existem, quais colunas cada uma tem, quais são as chaves — é nele que comandos como DESCRIBE vão buscar a resposta.

4. Panorama de mercado

Existem dezenas de SGBDs no mercado; vocês vão usar o MySQL nas próximas aulas práticas, mas vale a pena conhecer o cenário mais amplo:

Quatro SGBDs relacionais populares
SGBD Licença Perfil típico de uso
PostgreSQL Código aberto Sistemas que exigem recursos avançados de SQL, tipos de dados customizados e forte aderência a padrões.
MySQL Código aberto (com versão comercial) Aplicações web de médio e grande porte; muito usado junto com PHP, Node e frameworks web em geral.
Oracle Database Proprietária Grandes sistemas corporativos com exigências pesadas de desempenho, auditoria e suporte contratado.
SQLite Código aberto Banco embarcado: roda dentro do próprio aplicativo (apps mobile, ferramentas desktop), sem um servidor separado.

Conceito: embarcado × cliente-servidor

PostgreSQL, MySQL e Oracle seguem o modelo cliente-servidor: o SGBD roda como um processo separado (às vezes em outra máquina), e as aplicações se conectam a ele pela rede — foi esse modelo que vocês já usaram no MySQL Workbench. O SQLite é embarcado: o banco inteiro é um único arquivo, lido e escrito diretamente pelo próprio aplicativo, sem processo de servidor nem rede envolvida.

🤔 Confira se entendeu

Dois usuários tentam atualizar a mesma linha de uma tabela ao mesmo tempo. Qual função do SGBD entra em ação?

O controle de concorrência, que coordena os acessos simultâneos para que uma atualização não sobrescreva a outra de forma inconsistente.

Por que um app mobile offline-first costuma preferir SQLite a um SGBD cliente-servidor como o PostgreSQL?

Porque o SQLite é embarcado: não exige um servidor de banco rodando separadamente nem conexão de rede, já que o banco é um arquivo local lido diretamente pelo aplicativo.
