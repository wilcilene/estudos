Window functions, CTEs e uma primeira ideia de índices

Com JOIN, GROUP BY e subconsultas, vocês já resolvem a maioria dos problemas reais. Agora eu quero mostrar dois recursos que deixam consultas complexas muito mais legíveis — e fechar com uma explicação de por que algumas consultas são rápidas e outras, lentas. O cenário de hoje é o painel de telemetria de uma frota de foguetes.

O que vocês vão aprender aqui

  • Calcular um ranking por grupo com funções de janela (OVER, PARTITION BY).
  • Calcular um total acumulado com SUM() OVER (ORDER BY ...).
  • Organizar uma consulta em etapas nomeadas com WITH (CTE).
  • Entender, em termos gerais, por que um índice acelera uma consulta.

1. O cenário: telemetria de lançamentos

🚀 Base de lançamentos

Uma agência espacial registra cada lançamento de foguete na tabela lancamento: qual base foi usada, a data, a altitude máxima atingida e o combustível restante ao fim da missão.

CREATE TABLE lancamento (
  id_lancamento INT PRIMARY KEY AUTO_INCREMENT,
  nome_foguete VARCHAR(60) NOT NULL,
  base_lancamento VARCHAR(40) NOT NULL,
  data_lancamento DATE NOT NULL,
  altitude_km DECIMAL(8,2) NOT NULL,
  combustivel_restante_pct DECIMAL(5,2) NOT NULL
);

2. Window functions: calculando sem perder o detalhe

Uma função de agregação comum (como AVG com GROUP BY) resume várias linhas em uma só. Uma window function calcula algo sobre um grupo de linhas, mas sem colapsar o resultado — cada linha original continua aparecendo.

SELECT nome_foguete,
       base_lancamento,
       altitude_km,
       RANK() OVER (
         PARTITION BY base_lancamento
         ORDER BY altitude_km DESC
       ) AS posicao_na_base
FROM lancamento;
Linha a linha: ranking de altitude por base
TrechoO que significa
RANK() A função de janela em si: atribui uma posição de ranking a cada linha. Em caso de empate, duas linhas recebem a mesma posição e a próxima posição é pulada (ex.: 1, 1, 3).
OVER (...) Define a "janela": o conjunto de linhas sobre o qual RANK() é calculado para cada linha atual.
PARTITION BY base_lancamento Reinicia a contagem para cada base — ou seja, o ranking é calculado dentro de cada base separadamente, não no total geral.
ORDER BY altitude_km DESC Dentro de cada base, ordena da maior altitude para a menor antes de numerar.

Conceito: RANK() × ROW_NUMBER() × DENSE_RANK()

ROW_NUMBER() sempre numera de forma única (1, 2, 3, 4...), mesmo com empates. RANK() repete a posição em empates e pula números depois (1, 1, 3, 4). DENSE_RANK() repete a posição em empates, mas não pula números depois (1, 1, 2, 3).

Outro uso comum é um total acumulado — por exemplo, o combustível total consumido pela frota ao longo do tempo:

SELECT data_lancamento,
       nome_foguete,
       SUM(100 - combustivel_restante_pct) OVER (
         ORDER BY data_lancamento
       ) AS consumo_acumulado
FROM lancamento;

Sem PARTITION BY, a janela é a tabela inteira; com ORDER BY dentro do OVER, cada linha soma o valor das linhas anteriores — é assim que se constrói um total corrido.

3. CTEs: dando nome às etapas de uma consulta

Uma Common Table Expression (CTE) é um resultado temporário, nomeado, que existe só durante aquela consulta — ajuda a quebrar uma consulta complexa em passos legíveis:

WITH media_por_base AS (
  SELECT base_lancamento, AVG(altitude_km) AS altitude_media
  FROM lancamento
  GROUP BY base_lancamento
)
SELECT l.nome_foguete, l.base_lancamento, l.altitude_km, m.altitude_media
FROM lancamento AS l
JOIN media_por_base AS m ON m.base_lancamento = l.base_lancamento
WHERE l.altitude_km > m.altitude_media;
Linha a linha: foguetes acima da média da própria base
TrechoO que significa
WITH media_por_base AS (...) Define uma tabela temporária chamada media_por_base, calculada pela consulta entre parênteses — a altitude média de cada base.
JOIN media_por_base AS m ON ... A consulta principal usa media_por_base como se fosse uma tabela normal, juntando cada lançamento com a média da sua própria base.
WHERE l.altitude_km > m.altitude_media; Mantém só os lançamentos que superaram a média da própria base.

O mesmo resultado seria possível com uma subconsulta no FROM, mas o WITH deixa a intenção de cada etapa muito mais clara — e pode ser reaproveitado várias vezes na mesma consulta, enquanto uma subconsulta teria que ser repetida.

4. Por que algumas consultas são rápidas — uma primeira ideia de índice

Sem ajuda, o SGBD responde a um WHERE base_lancamento = 'Alcântara' lendo linha por linha, do início ao fim da tabela — uma varredura completa (table scan). Um índice é uma estrutura auxiliar que organiza os valores de uma coluna de um jeito que permite pular direto para o trecho relevante, sem ler tudo.

Dois tipos de índice, duas situações diferentes
EstruturaComo funcionaMelhor para
B-tree Organiza os valores em uma árvore balanceada, mantendo-os ordenados. Igualdade (=), faixas (BETWEEN, >, <) e ordenação (ORDER BY) — é o padrão da maioria dos SGBDs, inclusive o MySQL.
Hashing Aplica uma função que transforma o valor em um endereço direto, sem manter ordem. Buscas por igualdade exata — muito rápido para =, mas inútil para faixas ou ordenação, já que não existe noção de "próximo valor".

⚠️ Índice não é de graça

Todo índice acelera leitura, mas desacelera um pouco a escrita: a cada INSERT, UPDATE ou DELETE, o SGBD também precisa atualizar os índices daquela tabela. Por isso não criamos índice em toda coluna — priorizamos as colunas mais usadas em WHERE, JOIN e ORDER BY. A boa notícia é que, como vocês já viram, toda PRIMARY KEY e toda coluna UNIQUE já ganham um índice automaticamente.

🤔 Confira se entendeu

Qual a diferença entre usar GROUP BY e usar uma window function para calcular a altitude média por base?

GROUP BY colapsa as linhas em uma por base, perdendo o detalhe de cada lançamento individual. Uma window function (com PARTITION BY) calcula o mesmo valor, mas mantém todas as linhas originais, cada uma mostrando a média do seu grupo ao lado dos próprios dados.

Por que um índice hashing não ajudaria em uma consulta com ORDER BY altitude_km?

Porque hashing não preserva nenhuma noção de ordem entre os valores — ele só permite localizar rapidamente um valor exato, não percorrer os dados em sequência crescente ou decrescente.
