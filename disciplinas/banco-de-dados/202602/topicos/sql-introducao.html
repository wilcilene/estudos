Linguagens SQL

Introdução ao SQL: SELECT, WHERE e ORDER BY

A partir de agora a gente conversa com o banco na língua dele: o SQL. Antes de criar qualquer tabela (isso fica para o próximo tópico, de DDL), eu quero que vocês aprendam a perguntar coisas a um banco que já existe. Vamos usar como cenário a central de monitoramento de uma frota de robôs de entrega.

O que vocês vão aprender aqui

  • Entender o que é o padrão SQL (ISO/ANSI) e por que ele existe.
  • Ler e escrever a estrutura básica de um SELECT.
  • Filtrar linhas com WHERE e os principais operadores de comparação.
  • Ordenar resultados com ORDER BY e limitar quantidade com LIMIT.

1. O cenário: a frota de robôs

🤖 A central de monitoramento

Imaginem uma empresa de entregas que usa robôs autônomos. Toda a frota é monitorada por uma única tabela, robo_entrega, que guarda o estado de cada robô em tempo real. É nessa tabela que vamos praticar nossas primeiras consultas.

2. O padrão SQL

SQL (Structured Query Language) é um padrão definido pela ISO e pela ANSI, o que significa que a sintaxe básica — SELECT, WHERE, ORDER BY — funciona de forma muito parecida em qualquer SGBD relacional: MySQL, PostgreSQL, Oracle ou SQL Server. Cada SGBD acrescenta pequenas particularidades por cima do padrão (por exemplo, a forma de fazer AUTO_INCREMENT varia entre eles), mas o núcleo que vocês vão aprender aqui é transferível.

3. A estrutura do SELECT

Toda consulta começa pedindo "quais colunas eu quero ver" e "de qual tabela":

SELECT codigo, cidade, bateria_pct
FROM robo_entrega;
Linha a linha: primeiro SELECT
TrechoO que significa
SELECT codigo, cidade, bateria_pct Diz quais colunas devem aparecer no resultado, na ordem escolhida — aqui, só três das seis colunas da tabela.
FROM robo_entrega; Diz de qual tabela os dados vêm. O ponto e vírgula encerra o comando.

Para trazer todas as colunas sem digitar o nome de cada uma, usamos o asterisco:

SELECT * FROM robo_entrega;

⚠️ Cuidado com o *

SELECT * é ótimo para explorar uma tabela pequena durante o estudo, mas em código de produção eu peço que vocês sempre listem as colunas que realmente precisam — isso deixa a consulta mais rápida e evita que ela quebre se alguém adicionar uma coluna nova na tabela depois.

4. Filtrando linhas com WHERE

O SELECT sozinho traz todas as linhas. Para trazer só os robôs que interessam, usamos WHERE:

SELECT codigo, cidade, bateria_pct
FROM robo_entrega
WHERE bateria_pct < 20;
Linha a linha: filtrando por bateria baixa
TrechoO que significa
WHERE bateria_pct < 20 Só inclui no resultado as linhas em que o valor de bateria_pct é menor que 20 — ou seja, os robôs RX-02 (19%) e RX-05 (8%).

Conceito: por que não se usa = para comparar com NULL

NULL representa "valor desconhecido", então coluna = NULL nunca é considerado verdadeiro pelo SQL — nem quando a coluna realmente está vazia. Por isso existe o operador específico IS NULL (e IS NOT NULL para o caso contrário).

5. Ordenando com ORDER BY e limitando com LIMIT

SELECT codigo, cidade, bateria_pct
FROM robo_entrega
ORDER BY bateria_pct ASC
LIMIT 3;
Linha a linha: os três robôs com menos bateria
TrechoO que significa
ORDER BY bateria_pct ASC Ordena o resultado pela coluna bateria_pct, do menor para o maior (ASC = ascendente; DESC faria o caminho contrário).
LIMIT 3; Depois de ordenar, mantém só as três primeiras linhas do resultado — útil para perguntas como "quais são os robôs mais críticos agora?".

Dá para combinar tudo o que vimos em uma única consulta:

SELECT codigo, cidade, bateria_pct, status
FROM robo_entrega
WHERE status <> 'manutencao'
ORDER BY bateria_pct ASC
LIMIT 2;

Essa consulta lê assim, de trás para frente no raciocínio: "me dê os 2 robôs com menos bateria, entre os que não estão em manutenção, mostrando código, cidade, bateria e status."

🤔 Confira se entendeu

Como eu escreveria uma consulta para listar os robôs de Joinville que estão com status 'em_rota', ordenados pelo código?

SELECT * FROM robo_entrega WHERE cidade = 'Joinville' AND status = 'em_rota' ORDER BY codigo;

Por que SELECT * FROM robo_entrega WHERE bateria_pct = NULL; nunca retorna nenhuma linha, mesmo que existam robôs sem bateria registrada?

Porque NULL significa "desconhecido", e o operador = nunca é verdadeiro ao comparar algo com NULL. O correto seria usar WHERE bateria_pct IS NULL.
