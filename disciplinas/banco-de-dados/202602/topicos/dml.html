DDL e DML

DML: povoando e mantendo os dados com INSERT, UPDATE e DELETE

Vocês já sabem criar a estrutura (DDL) e já sabem perguntar coisas a uma tabela (SELECT). Agora falta a parte que efetivamente põe dados dentro dela, corrige o que está errado e remove o que não deve mais existir: a DML. Vamos praticar com o cadastro de um abrigo intergaláctico que recebe alienígenas resgatados de naves acidentadas.

O que vocês vão aprender aqui

  • Inserir uma ou várias linhas de uma vez com INSERT INTO ... VALUES.
  • Atualizar registros existentes com UPDATE ... SET ... WHERE.
  • Remover registros com DELETE FROM ... WHERE.
  • Adotar o hábito de validar um UPDATE/DELETE com um SELECT antes de executá-lo de verdade.

1. O cenário: o abrigo

👽 O abrigo intergaláctico

Depois que uma nave tem um problema, os sobreviventes são trazidos para um abrigo temporário até serem reencaminhados aos seus planetas. A tabela alienigena_resgatado já existe (ela foi criada com DDL, exatamente como vocês praticaram no tópico anterior) — agora é nossa vez de povoá-la e mantê-la atualizada.

CREATE TABLE alienigena_resgatado (
  id_registro INT PRIMARY KEY AUTO_INCREMENT,
  nome_registro VARCHAR(80) NOT NULL,
  especie VARCHAR(60) NOT NULL,
  planeta_origem VARCHAR(60) NOT NULL,
  estado_saude VARCHAR(20) NOT NULL DEFAULT 'em_observacao',
  data_resgate DATE NOT NULL,
  setor_abrigo CHAR(1) NOT NULL
);

Essa tabela é só o ponto de partida para os exemplos a seguir — já criada, já existe no banco, pronta para receber linhas.

2. Inserindo registros com INSERT

INSERT INTO alienigena_resgatado
  (nome_registro, especie, planeta_origem, estado_saude, data_resgate, setor_abrigo)
VALUES
  ('Zyx-7', 'Crystalloide', 'Vexor IV', 'estavel', '2026-09-14', 'A');
Linha a linha: primeiro INSERT
TrechoO que significa
INSERT INTO alienigena_resgatado Diz em qual tabela a nova linha vai entrar.
(nome_registro, especie, planeta_origem, estado_saude, data_resgate, setor_abrigo) Lista explicitamente as colunas que vamos preencher, na ordem escolhida por nós. Note que id_registro não aparece: ele é AUTO_INCREMENT, então o próprio MySQL gera o valor.
VALUES ('Zyx-7', 'Crystalloide', 'Vexor IV', 'estavel', '2026-09-14', 'A'); Traz um valor para cada coluna listada acima, na mesma ordem. Textos e datas vão entre aspas simples; números, não.

⚠️ Sempre liste as colunas

É possível escrever INSERT INTO alienigena_resgatado VALUES (...) sem listar as colunas — mas aí o MySQL espera um valor para cada coluna da tabela, na ordem exata em que ela foi criada. Se alguém alterar a tabela no futuro e adicionar uma coluna no meio, esse INSERT "silencioso" passa a inserir os dados nas colunas erradas sem avisar ninguém. Por isso eu sempre peço para vocês listarem as colunas explicitamente, mesmo preenchendo todas.

Para inserir vários resgatados de uma vez, listamos vários grupos de valores separados por vírgula:

INSERT INTO alienigena_resgatado
  (nome_registro, especie, planeta_origem, estado_saude, data_resgate, setor_abrigo)
VALUES
  ('Mor-3', 'Fluidigena', 'Oceano de Thess', 'critico', '2026-09-15', 'B'),
  ('Kael-9', 'Crystalloide', 'Vexor IV', 'estavel', '2026-09-15', 'A'),
  ('Ix-1', 'Lumeno', 'Prisma Binário', 'em_observacao', '2026-09-16', 'C');

Cada grupo entre parênteses é uma linha nova; o SGBD insere as três de uma só vez, o que é bem mais rápido do que rodar três comandos INSERT separados.

3. Atualizando registros com UPDATE

Dias depois, o estado de saúde de Mor-3 melhora. Vamos atualizar só essa linha:

UPDATE alienigena_resgatado
SET estado_saude = 'estavel'
WHERE nome_registro = 'Mor-3';
Linha a linha: atualizando o estado de saúde
TrechoO que significa
UPDATE alienigena_resgatado Diz em qual tabela vamos alterar linhas existentes.
SET estado_saude = 'estavel' Diz qual coluna muda e para qual novo valor. Dá para atualizar várias colunas na mesma linha, separando com vírgula: SET estado_saude = 'estavel', setor_abrigo = 'A'.
WHERE nome_registro = 'Mor-3'; Escolhe quais linhas recebem a alteração. Sem essa cláusula, a alteração vale para todas as linhas da tabela.

🚨 O erro mais perigoso da DML

Um UPDATE sem WHERE altera a tabela inteira. Se vocês rodarem UPDATE alienigena_resgatado SET estado_saude = 'estavel'; sem a cláusula WHERE, todos os alienígenas do abrigo — inclusive os que estão em estado crítico — passam a constar como estáveis. Antes de apertar o raio de execução, confiram sempre se a linha do WHERE está mesmo lá.

4. Removendo registros com DELETE

Quando um alienígena é reencaminhado ao seu planeta de origem, o registro sai do abrigo:

DELETE FROM alienigena_resgatado
WHERE nome_registro = 'Kael-9';
Linha a linha: removendo um registro
TrechoO que significa
DELETE FROM alienigena_resgatado Diz de qual tabela as linhas serão removidas.
WHERE nome_registro = 'Kael-9'; Escolhe qual linha será removida. Assim como no UPDATE, sem WHERE a instrução remove todas as linhas da tabela — a estrutura continua existindo, mas fica vazia.

5. O hábito que evita desastres

A técnica que eu mais insisto com vocês: antes de rodar um UPDATE ou DELETE, rodem um SELECT com a mesma cláusula WHERE, só para ver quais linhas seriam afetadas.

  1. Escrevam a condição primeiro.

    Pensem em "quais linhas eu quero afetar" antes de pensar no comando.

  2. Testem com SELECT.

    SELECT * FROM alienigena_resgatado WHERE nome_registro = 'Mor-3'; — confiram se é exatamente a linha (ou as linhas) que vocês esperavam.

  3. Troquem o SELECT * FROM pelo comando real.

    Se o resultado do passo anterior estava certo, substituam SELECT * FROM tabela por UPDATE tabela SET ... ou DELETE FROM tabela, mantendo o mesmo WHERE.

  4. Confiram depois de executar.

    Rodem o SELECT de novo para confirmar que o resultado final é o esperado.

É por esse motivo, aliás, que SELECT entra junto com DML neste bloco de estudos: embora tecnicamente pertença à DQL (a linguagem de consulta), na prática ele é o instrumento que usamos o tempo todo para verificar o efeito de um INSERT, UPDATE ou DELETE antes e depois de executá-lo.

🤔 Confira se entendeu

Por que o INSERT não precisa (e não deve) informar um valor para id_registro?

Porque id_registro foi criado como AUTO_INCREMENT: o próprio MySQL gera o próximo valor automaticamente a cada nova linha.

Qual comando movería o registro de Ix-1 para o setor 'A' do abrigo?

UPDATE alienigena_resgatado SET setor_abrigo = 'A' WHERE nome_registro = 'Ix-1';
