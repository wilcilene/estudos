Caso Nº 11 · Aspectos Computacionais

Representação Computacional de Fórmulas Lógicas

Para que um computador raciocine sobre uma fórmula, ela precisa virar dado: uma estrutura que o código possa percorrer, avaliar e transformar.

Fórmulas como árvores sintáticas

A definição recursiva de fórmula bem formada (vista no caso sobre linguagem formal) já sugere a estrutura de dados ideal: uma árvore. Cada nó folha é uma variável proposicional; cada nó interno é um conectivo, com um filho (para ¬) ou dois filhos (para ∧, ∨, →, ↔), que são, eles mesmos, subfórmulas.

A fórmula (p ∧ q) → r, por exemplo, vira uma árvore cuja raiz é →, com filho esquerdo ∧ (que por sua vez tem filhos p e q) e filho direito r.

Representando em código

Estrutura de dados 
// Uma variável proposicional
{ tipo: "var", nome: "p" }

// Uma fórmula composta: (p ∧ q) → r
{
  tipo: "implica",
  esquerda: {
    tipo: "e",
    esquerda: { tipo: "var", nome: "p" },
    direita:  { tipo: "var", nome: "q" }
  },
  direita: { tipo: "var", nome: "r" }
}

Cada objeto aninhado corresponde a um nó da árvore sintática — o código apenas segue a mesma recursão da definição formal.

Um pequeno verificador de pistas

Para avaliar uma fórmula dado um conjunto de valores-verdade (uma "interpretação"), basta uma função recursiva: se o nó é uma variável, consulta-se o valor atribuído a ela; se é um conectivo, avaliam-se os filhos recursivamente e combina-se o resultado segundo a tabela-verdade daquele conectivo. Essa é, literalmente, a lógica por trás de um verificador automático de pistas: dado um cenário (quem estava onde), o programa confirma se cada fórmula do caso se sustenta.

Exercício

Como você representaria a fórmula ¬p ∨ q como uma árvore (em texto, indicando raiz e filhos)?

Ver resposta

Raiz: ∨. Filho esquerdo: ¬ com filho p. Filho direito: q. Em notação de objeto: {tipo:"ou", esquerda:{tipo:"nao", filho:{tipo:"var",nome:"p"}}, direita:{tipo:"var",nome:"q"}}.
