Caso Nº 19 · Substituição

Substituição e Unificação

Uma regra geral e uma pista concreta só se encontram quando conseguimos fazer as duas coincidirem. Esse encaixe se chama unificação.

Ao final deste caso, vocês vão saber
  • aplicar e compor substituições, respeitando a aplicação simultânea;
  • definir unificador e unificador mais geral (MGU);
  • executar o algoritmo de unificação passo a passo, incluindo a verificação de ocorrência;
  • reconhecer os dois motivos de falha: conflito de símbolos e ciclo;
  • ler e adaptar uma implementação da unificação em Python.

Substituição

Uma substituição σ = {x₁/t₁, ..., xₙ/tₙ} troca cada variável xᵢ pelo termo tᵢ. Escrevemos φσ para o resultado de aplicar σ em φ. Com σ = {j/j1, c/Faca}: 

Tem(j, c)σ  =  Tem(j1, Faca)

O resultado se chama instância da fórmula original. É assim que uma regra geral (“quem mostra uma carta tem a carta”) é aplicada a um caso concreto. Dois cuidados:

  • A aplicação é simultânea. P(x, y){x/y, y/a} dá P(y, a), e não P(a, a): o y que entrou no lugar de x não é substituído de novo.
  • Só se substituem variáveis, nunca constantes. {Faca/x} não é uma substituição.

Composição

A composição σθ significa “aplicar σ e depois θ”: φ(σθ) = (φσ)θ. Para calcular, apliquem θ nos termos de σ e acrescentem os pares de θ cujas variáveis σ não mencionava.

Compondo 
σ = {x/f(y)}      θ = {y/a}
σθ = {x/f(a), y/a}

Conferindo em P(x, y):   P(x, y)σ = P(f(y), y)   e depois   θ  →  P(f(a), a)  ✓

Unificação e unificador mais geral

Um unificador de duas expressões é uma substituição que as torna idênticas. Para P(x, y) e P(a, z), estes são unificadores: 

σ₁ = {x/a, y/z}            resultado: P(a, z)
σ₂ = {x/a, y/b, z/b}       resultado: P(a, b)

O σ₂ fixa mais do que o necessário: ele é σ₁ seguido de {z/b}. Dizemos que σ₁ é mais geral. O unificador mais geral (MGU, de most general unifier) é aquele do qual todos os outros se obtêm por composição. O teorema de Robinson (1965) garante: se duas expressões são unificáveis, existe um MGU, único a menos de renomear variáveis. Na resolução, sempre usamos o MGU, para não perder generalidade cedo demais.

O algoritmo de unificação

Escrevam o problema como uma lista de equações s = t e apliquem as regras até não sobrar nada a fazer:

SituaçãoAção
f(s₁, ..., sₙ) = f(t₁, ..., tₙ)Decompor em s₁ = t₁, ..., sₙ = tₙ.
f(...) = g(...) com f ≠ g (ou aridades diferentes)Falha por conflito. Duas constantes diferentes também conflitam.
x = xApagar a equação.
t = x com t que não é variávelInverter para x = t.
x = t com x aparecendo dentro de tFalha pela verificação de ocorrência (occurs check).
x = t com x fora de tEliminar: registrar x/t e trocar x por t em todas as outras equações.
Exemplo clássico 
P(x, f(y))  =  P(a, f(g(z)))
→ x = a,  f(y) = f(g(z))        decompor
→ x = a,  y = g(z)              decompor
MGU: {x/a, y/g(z)}              resultado: P(a, f(g(z)))
Exemplo do Detetive

A regra fala de Mostrou(j, aDireita(j), c); o fato é Mostrou(j1, k, Faca).

j = j1,   aDireita(j) = k,   c = Faca        decompor
j/j1  →   aDireita(j1) = k,  c = Faca          eliminar j
          k = aDireita(j1)                     inverter
MGU: {j/j1, k/aDireita(j1), c/Faca}

Lendo: a jogadora k do fato só pode ser a que está à direita de j1, e a carta é a Faca.

Quando a unificação falha

  • Conflito: EsteveEm(Mordomo, Biblioteca) e EsteveEm(Jardineiro, y). A primeira equação é Mordomo = Jardineiro, duas constantes diferentes. Nenhuma substituição resolve.
  • Ciclo: P(x, x) e P(y, aDireita(y)). Depois de x/y, sobra y = aDireita(y): y teria de ser a jogadora à direita de si mesma, um termo infinito aDireita(aDireita(...)). A verificação de ocorrência barra isso.
Erro comum

Esquecer a verificação de ocorrência. Sem ela, o algoritmo “unifica” x com f(x) e a resolução pode “provar” coisas falsas. Curiosidade de engenharia: o Prolog, por desempenho, pula essa verificação por padrão; quando ela importa, usa-se o predicado unify_with_occurs_check/2.

Uma implementação em Python

Termos compostos são tuplas (símbolo, arg1, ...); variáveis são textos em minúsculas; constantes começam com maiúscula (por isso J1).

def eh_var(t):
    return isinstance(t, str) and t[0].islower()

def aplicar(t, s):
    if eh_var(t):
        return aplicar(s[t], s) if t in s else t
    if isinstance(t, tuple):
        return (t[0],) + tuple(aplicar(a, s) for a in t[1:])
    return t

def ocorre(x, t):
    if t == x:
        return True
    return isinstance(t, tuple) and any(ocorre(x, a) for a in t[1:])

def unificar(a, b, s=None):
    s = {} if s is None else s
    a, b = aplicar(a, s), aplicar(b, s)
    if a == b:
        return s
    if eh_var(a):
        return None if ocorre(a, b) else {**s, a: b}
    if eh_var(b):
        return unificar(b, a, s)
    if isinstance(a, tuple) and isinstance(b, tuple) \
            and a[0] == b[0] and len(a) == len(b):
        for x, y in zip(a[1:], b[1:]):
            s = unificar(x, y, s)
            if s is None:
                return None
        return s
    return None                                    # conflito de símbolos

regra = ("Mostrou", "j", ("aDireita", "j"), "c")
fato  = ("Mostrou", "J1", "k", "Faca")
print(unificar(regra, fato))
# {'j': 'J1', 'k': ('aDireita', 'J1'), 'c': 'Faca'}

A função devolve None quando não há unificador. O dicionário pode ter variáveis que apontam para termos com outras variáveis; aplicar segue essas ligações até o fim.

No Detetive

Unificar é o que vocês fazem ao ouvir um palpite e consultar as regras do bloco: “quem mostra uma carta tem a carta” casa com “a jogadora à direita da Jogadora 1 mostrou a Faca” quando j vira j1 e c vira Faca. Se o palpite falasse de uma carta diferente da que a regra exige, haveria conflito, e a regra simplesmente não se aplicaria.

Exercício 1 · Unificador

Encontrem o MGU de UsouArma(x, Faca) e UsouArma(Mordomo, y).

Ver resposta

{x/Mordomo, y/Faca}. As duas viram UsouArma(Mordomo, Faca).

Exercício 2 · Com funções

Encontrem o MGU de Q(x, f(x)) e Q(f(y), z).

Ver resposta

Equações x = f(y) e f(x) = z. Eliminando x: z = f(f(y)). MGU: {x/f(y), z/f(f(y))}. Resultado: Q(f(y), f(f(y))).

Exercício 3 · Unifica ou falha?

Para cada par, dê o MGU ou o motivo da falha: (a) P(x, x) e P(Mordomo, Faca); (b) P(x, g(x)) e P(g(y), y).

Ver resposta

(a) Falha por conflito: depois de x/Mordomo, sobra Mordomo = Faca. (b) Falha por ocorrência: de x = g(y), a segunda equação vira g(g(y)) = y, e y aparece dentro de g(g(y)).

Para guardar
  • Substituição troca variáveis por termos, todas ao mesmo tempo.
  • Unificador torna duas expressões idênticas; o MGU fixa só o necessário.
  • Algoritmo: decompor, apagar, inverter, eliminar; falhar por conflito ou por ocorrência.
  • Sem verificação de ocorrência, a unificação aceita termos infinitos e a lógica fica incorreta.
