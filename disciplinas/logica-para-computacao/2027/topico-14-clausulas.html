Caso Nº 14 · Princípio da Resolução

Cláusulas e Representação por Conjuntos

Em forma normal conjuntiva, cada pista vira uma cláusula e o caso inteiro vira um conjunto de cláusulas, pronto para ser cruzado.

Ao final deste caso, vocês saberão
  • escrever cláusulas e fórmulas em FNC na notação de conjuntos;
  • explicar o significado da cláusula vazia e do conjunto vazio de cláusulas;
  • reconhecer cláusulas unitárias, tautológicas, de Horn e cláusulas subsumidas;
  • executar o algoritmo de encadeamento para frente, que decide cláusulas de Horn em tempo linear;
  • representar um conjunto de cláusulas em código e no formato DIMACS.

Por que usar conjuntos

Imaginem…

Uma cláusula é um saquinho de bolinhas, e cada bolinha é um literal. Dentro do saquinho, não importa a ordem das bolinhas, e duas bolinhas iguais valem como uma só. A fórmula inteira é uma caixa cheia desses saquinhos; dentro da caixa, também não importa a ordem dos saquinhos.

A regra do jogo: para “cumprir” um saquinho, basta que uma das bolinhas dele seja verdadeira. Para “cumprir” a caixa, é preciso cumprir todos os saquinhos.

Numa cláusula, a ordem dos literais não importa (comutatividade) e repetir um literal não muda nada (idempotência). Por isso, podemos escrever a cláusula como um conjunto de literais: p ∨ ¬q ∨ r vira {p, ¬q, r}. Do mesmo jeito, uma FNC é uma conjunção de cláusulas, em que ordem e repetição também não importam, então ela vira um conjunto de cláusulas: 

(p ∨ r) ∧ (q ∨ r) ∧ (¬p ∨ ¬q)     ⟶     { {p, r}, {q, r}, {¬p, ¬q} }

Leiam assim: a vírgula dentro de uma cláusula é um “ou”; a vírgula entre cláusulas é um “e”. Uma valoração satisfaz o conjunto quando satisfaz todas as cláusulas; ela satisfaz uma cláusula quando torna verdadeiro pelo menos um de seus literais.

Erro comum

Confundir { } (a cláusula vazia, falsa) com ∅ (nenhuma cláusula, verdadeiro). Encontrar □ durante a resolução é o sinal de que o conjunto é insatisfatível; ficar sem cláusulas para satisfazer é sinal de sucesso na busca de modelos.

Subsunção: cláusulas que sobram

Imaginem…

Duas regras na geladeira: “escove os dentes” e “escove os dentes ou passe fio dental”. Quem cumpre a primeira já cumpre a segunda automaticamente. A segunda regra ficou inútil: pode sair da geladeira.

Se C ⊆ D, dizemos que C subsume D. Nesse caso, D é redundante: toda valoração que satisfaz C também satisfaz D. Por exemplo, {p} subsume {p, q}. Remover cláusulas subsumidas e tautológicas deixa o conjunto menor sem mudar o seu significado, e os algoritmos agradecem.

Cláusulas de Horn

Uma cláusula de Horn tem no máximo um literal positivo. Elas são especiais porque podem ser lidas como regras do tipo “se isto e aquilo, então aquilo outro”:

TipoCláusulaLeitura como regra
Regra{¬p, ¬q, r}p ∧ q → r
Fato{r}r é verdade
Objetivo (restrição){¬p, ¬q}p ∧ q não pode acontecer

Para conjuntos de cláusulas de Horn, a satisfatibilidade é resolvida em tempo linear, sem o risco exponencial do SAT geral. O algoritmo se chama encadeamento para frente e é tão simples quanto um jogo de dominó:

  1. Comecem com todas as variáveis falsas.
  2. Marquem como verdadeira toda variável que aparece num fato.
  3. Sempre que todas as condições de uma regra estiverem marcadas, marquem a conclusão dela. Repitam até nada mudar.
  4. Se alguma restrição tiver todas as suas variáveis marcadas, o conjunto é insatisfatível; caso contrário, as marcas formam um modelo (o menor possível).
Encadeamento para frente no Detetive 
Fatos:       L (há lama na Cozinha)        P (a Pá sumiu)
Regras:      L ∧ P → J  (então o Jardineiro esteve lá)
             J → C      (então o crime foi na Cozinha)
Restrição:   ¬C ∨ ¬B    (não pode ter sido na Cozinha e na Biblioteca)

Marcas: L, P  →  J  →  C.   A restrição exige ¬B; B não foi marcada.  SAT.

É esse o formato da linguagem Prolog, que encontraremos no Caso 20.

Cláusulas no computador

Numa implementação, uma cláusula é um conjunto (ou um vetor ordenado) de literais, e o literal é um inteiro com sinal: a variável k vira k e ¬k vira -k. Esse é o formato DIMACS, lido por praticamente todos os resolvedores SAT: 

c Pistas do exemplo: 1 = p, 2 = q, 3 = r
p cnf 3 3
1 3 0
2 3 0
-1 -2 0

A linha p cnf 3 3 diz que há 3 variáveis e 3 cláusulas; cada cláusula termina em 0; linhas com c são comentários.

Em Python, a mesma ideia fica assim, e é exatamente a representação usada no algoritmo do Caso 16:

clausulas = [frozenset({1, 3}), frozenset({2, 3}), frozenset({-1, -2})]
tautologica = lambda c: any(-x in c for x in c)
subsume = lambda c, d: c <= d      # c ⊆ d
No Detetive

Vejam como o bloco de anotações vira um conjunto de cláusulas (cada variável quer dizer “a carta está no envelope”):

  • “Eu tenho a Faca”: {¬F}, uma cláusula unitária.
  • “O jogador à direita mostrou uma carta entre Mordomo, Veneno e Cozinha”: {¬M, ¬V, ¬C}, uma cláusula de Horn do tipo objetivo.
  • “O suspeito é Mordomo, Governanta ou Jardineiro”: {M, G, J}, que não é de Horn.

Se mais tarde vocês descobrem {¬M}, a pista {¬M, ¬V, ¬C} passa a ser subsumida e pode ser riscada do bloco: ela não acrescenta mais nada.

Exercício 1 · Notação de conjuntos

Escrevam como conjunto de cláusulas: (¬p ∨ q) ∧ (¬q ∨ p) ∧ p.

Ver resposta

{ {¬p, q}, {¬q, p}, {p} }. A última é unitária.

Exercício 2 · Limpando o conjunto

Simplifiquem { {p, q}, {p}, {q, ¬q, r}, {¬r, s}, {¬r, s, p} } removendo cláusulas tautológicas e subsumidas.

Ver resposta

{q, ¬q, r} é tautológica. {p} subsume {p, q} e {¬r, s, p}. Resultado: { {p}, {¬r, s} }.

Exercício 3 · Horn ou não?

Quais são de Horn: {¬a, b}, {a, b}, {¬a, ¬b, ¬c}, {c}?

Ver resposta

Todas, exceto {a, b}, que tem dois literais positivos.

Exercício 4 · Encadeamento para frente

Decidam se é satisfatível: fatos {a}, {b}; regras {¬a, ¬b, c}, {¬c, d}; restrição {¬d, ¬a}.

Ver resposta

Marcas: a, b; a primeira regra marca c; a segunda marca d. A restrição {¬d, ¬a} tem d e a marcadas: violada. O conjunto é insatisfatível.

Para guardar
  • Cláusula = conjunto de literais (“ou”, o saquinho); FNC = conjunto de cláusulas (“e”, a caixa).
  • □ é falsa (saquinho vazio); ∅ é verdadeiro (caixa vazia).
  • Cláusulas tautológicas e subsumidas podem ser removidas.
  • Cláusulas de Horn (no máximo um literal positivo) são regras, fatos e restrições; o encadeamento para frente decide o SAT delas em tempo linear.
  • DIMACS: variáveis como inteiros, negação como sinal de menos, 0 no fim.
