Caso Nº 11 · Aspectos Computacionais

Representação Computacional de Fórmulas Lógicas

Para o computador raciocinar sobre uma pista, ela precisa virar dado. Neste caso vocês vão ver como uma fórmula se transforma em estrutura de dados.

Ao final deste caso, vocês vão saber
  • representar fórmulas como árvores sintáticas em uma linguagem de programação;
  • escrever a gramática das fórmulas em BNF e entender como um parser a usa;
  • implementar a avaliação recursiva e analisar o seu custo;
  • gerar todas as valorações com números binários e reconhecer a ideia de DAG.

Da definição indutiva à estrutura de dados

No Caso 03, vimos que toda fórmula é uma variável, uma negação de fórmula ou um binário entre duas fórmulas. Essa definição já é, praticamente, a declaração de um tipo de dados recursivo: uma árvore em que cada folha é uma variável e cada nó interno é um conectivo com um filho (¬) ou dois filhos (∧, ∨, →, ↔).

A pista (B ∧ M) → C como objeto 
// JavaScript: cada nó guarda o tipo e os filhos
const pista = {
  t: "imp",
  a: { t: "and", a: { t: "var", n: "B" }, b: { t: "var", n: "M" } },
  b: { t: "var", n: "C" }
};
# Python: a mesma árvore com dataclasses
from dataclasses import dataclass

@dataclass
class Var:  nome: str
@dataclass
class Nao:  a: object
@dataclass

pista = Bin("imp", Bin("and", Var("B"), Var("M")), Var("C"))

Reparem que os parênteses desapareceram: o agrupamento está na forma da árvore.

A gramática e o parser

Para ler uma fórmula digitada como texto, precisamos de um parser (analisador sintático). Ele segue uma gramática escrita em BNF, com um nível para cada precedência do Caso 03, do conectivo mais fraco ao mais forte: 

bicond  ::= implica ( "↔" implica )*
implica ::= ou ( "→" implica )?        ← recursão à direita: → associa à direita
ou      ::= e ( "∨" e )*
e       ::= unario ( "∧" unario )*
unario  ::= "¬" unario | atomo
atomo   ::= VARIAVEL | "(" bicond ")"

Um parser de descida recursiva tem uma função para cada linha dessa gramática, e as funções chamam umas às outras. É exatamente assim que compiladores leem expressões aritméticas. Vocês encontram um parser completo, funcionando, no exemplo de entrega da Apresentação 1.

Avaliação recursiva

Para avaliar uma fórmula numa valoração, percorremos a árvore em pós-ordem: primeiro os filhos, depois o conectivo.

function avaliar(f, val) {          // val: { B: true, M: false, C: true }
  switch (f.t) {
    case "var": return val[f.n];
    case "not": return !avaliar(f.a, val);
    case "and": return avaliar(f.a, val) && avaliar(f.b, val);
    case "or":  return avaliar(f.a, val) || avaliar(f.b, val);
    case "imp": return !avaliar(f.a, val) || avaliar(f.b, val);
    case "iff": return avaliar(f.a, val) === avaliar(f.b, val);
  }
}

Cada nó é visitado uma vez, então o custo é O(n), com n o tamanho da fórmula. Guardem isso: verificar se uma valoração satisfaz uma fórmula é rápido. O difícil, como veremos no Caso 12, é encontrar uma valoração que satisfaça.

Notem também que a função recursiva espelha a definição indutiva: um caso por regra de formação. Provar que ela termina e está correta é uma indução estrutural (Caso 03).

Valorações como números binários

Com n variáveis numeradas de 0 a n − 1, cada valoração é um número de n bits: o bit k diz o valor da variável k. Para percorrer a tabela-verdade inteira, basta um laço de 0 a 2ⁿ − 1. 

function tabela(f, vars) {
  const linhas = [];
  for (let i = 0; i < (1 << vars.length); i++) {
    const val = {};
    vars.forEach((x, k) => { val[x] = Boolean(i & (1 << k)); });
    linhas.push({ val, resultado: avaliar(f, val) });
  }
  return linhas;
}

Na prática, essa representação também é usada para guardar conjuntos de cartas com uma única variável inteira: cada bit é uma carta.

No DAG, uma subfórmula que aparece várias vezes vira um único nó, apontado por vários pais. Em (p ∧ q) ∨ ¬(p ∧ q), o nó p ∧ q é armazenado e avaliado uma só vez. Essa ideia vai reaparecer na transformação de Tseitin (Caso 13).

No Detetive

Um “verificador de bloco de anotações” é só isto: uma lista de pistas em forma de árvore e a função avaliar. Dado um envelope candidato (uma valoração), o programa confere, pista por pista, se ele é compatível com tudo o que foi visto. Com 324 envelopes possíveis, testar todos leva milissegundos. É assim que o jogo da Apresentação 1 confere a escalação do time de vôlei.

Exercício 1 · Desenhe a árvore

Representem ¬p ∨ q → r como árvore e como objeto JavaScript.

Ver resposta

Pela precedência, é ((¬p) ∨ q) → r. Raiz →; filho esquerdo ∨ (com filhos ¬p e q); filho direito r.

{ t:"imp",

Exercício 2 · Contando nós

Escrevam uma função recursiva que conte quantos nós uma fórmula tem. Quantos nós tem (B ∧ M) → C?

Ver resposta 
function nos(f) {
  if (f.t === "var") return 1;
  if (f.t === "not") return 1 + nos(f.a);
  return 1 + nos(f.a) + nos(f.b);
}

Para (B ∧ M) → C: 5 nós (→, ∧, B, M, C).

Exercício 3 · Bits

Com as variáveis [B, M, C] nos bits 0, 1 e 2, que valoração corresponde ao número 5?

Ver resposta

5 = 101 em binário: bit 0 = 1, bit 1 = 0, bit 2 = 1. Logo, B = V, M = F, C = V.

Para guardar
  • Fórmula = árvore: folhas são variáveis, nós internos são conectivos.
  • A gramática em BNF com um nível por precedência guia o parser de descida recursiva.
  • Avaliar custa O(n); percorrer todas as valorações custa O(n · 2ⁿ).
  • Valorações podem ser números binários; DAGs compartilham subfórmulas iguais.
