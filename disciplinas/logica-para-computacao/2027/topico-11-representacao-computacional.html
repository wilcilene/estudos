Caso Nº 11 · Aspectos Computacionais

Representação Computacional de Fórmulas Lógicas

Para o computador raciocinar sobre uma pista, ela precisa virar dado. Neste caso vocês verão como uma fórmula se transforma em estrutura de dados.

Ao final deste caso, vocês saberão
  • representar fórmulas como árvores sintáticas em uma linguagem de programação;
  • escrever a gramática das fórmulas em BNF e entender as duas etapas da leitura: análise léxica e análise sintática;
  • ler e adaptar um parser de descida recursiva completo;
  • implementar a avaliação recursiva e analisar o seu custo;
  • gerar todas as valorações com números binários e reconhecer a ideia de DAG.

Da definição indutiva à estrutura de dados

Imaginem…

Uma árvore genealógica desenhada de cabeça para baixo. No topo está a avó; abaixo, os filhos; mais abaixo, os netos, que não têm filhos. Numa fórmula, o topo é o conectivo principal, os “filhos” são as partes que ele liga e os “netos sem filhos” são as variáveis. Guardar uma fórmula no computador é guardar essa árvore.

No Caso 03, vimos que toda fórmula é uma variável, uma negação de fórmula ou um binário entre duas fórmulas. Essa definição já é, praticamente, a declaração de um tipo de dados recursivo: uma árvore em que cada folha é uma variável e cada nó interno é um conectivo com um filho (¬) ou dois filhos (∧, ∨, →, ↔).

A pista (B ∧ M) → C como objeto 
// JavaScript: cada nó guarda o tipo e os filhos
const pista = {
  t: "imp",
  a: { t: "and", a: { t: "var", n: "B" }, b: { t: "var", n: "M" } },
  b: { t: "var", n: "C" }
};
# Python: a mesma árvore com dataclasses
from dataclasses import dataclass

@dataclass
class Var:  nome: str
@dataclass
class Nao:  a: object
@dataclass

pista = Bin("imp", Bin("and", Var("B"), Var("M")), Var("C"))

Reparem que os parênteses desapareceram: o agrupamento está na forma da árvore.

Lendo texto: análise léxica e sintática

Imaginem…

Uma criança aprendendo a ler faz duas coisas. Primeiro, separa as letras em palavras (“o”, “gato”, “dorme”). Depois, entende como as palavras se organizam numa frase (quem é o sujeito, qual é o verbo). Um programa que lê fórmulas faz o mesmo: primeiro separa os símbolos (análise léxica), depois monta a árvore (análise sintática).

  1. Análise léxica (o tokenizer): transforma o texto "(B ∧ M) → C" na lista de peças ["(", "B", "∧", "M", ")", "→", "C"], ignorando espaços.
  2. Análise sintática (o parser): lê a lista e monta a árvore, seguindo uma gramática.

A gramática é escrita em BNF, com um nível para cada precedência do Caso 03, do conectivo mais fraco ao mais forte. Cada linha diz “uma coisa deste tipo é feita destas peças”: 

bicond  ::= implica ( "↔" implica )*
implica ::= ou ( "→" implica )?        ← recursão à direita: → associa à direita
ou      ::= e ( "∨" e )*
e       ::= unario ( "∧" unario )*
unario  ::= "¬" unario | atomo
atomo   ::= VARIAVEL | "(" bicond ")"

Um parser de descida recursiva tem uma função para cada linha dessa gramática, e as funções chamam umas às outras. É exatamente assim que compiladores leem expressões aritméticas. Este é um parser completo, em poucas linhas: 

function parse(texto) {
  const tokens = texto.match(/[A-Za-z]\w*|[¬∧∨→↔()]/g) || [];   // análise léxica
  let i = 0;
  const ver = () => tokens[i];
  function bicond()  { let a = implica(); while (ver() === "↔") { i++; a = { t: "iff", a, b: implica() }; } return a; }
  function implica() { const a = ou(); if (ver() === "→") { i++; return { t: "imp", a, b: implica() }; } return a; }
  function ou()      { let a = conj(); while (ver() === "∨") { i++; a = { t: "or", a, b: conj() }; } return a; }
  function conj()    { let a = unario(); while (ver() === "∧") { i++; a = { t: "and", a, b: unario() }; } return a; }
  function unario()  { if (ver() === "¬") { i++; return { t: "not", a: unario() }; } return atomo(); }
  function atomo() {
    const t = ver();
    if (t === "(") { i++; const f = bicond(); if (ver() !== ")") throw new Error("faltou ')'"); i++; return f; }
    if (t && /^[A-Za-z]/.test(t)) { i++; return { t: "var", n: t }; }
    throw new Error("símbolo inesperado: " + t);
  }
  const f = bicond();
  if (i < tokens.length) throw new Error("sobrou: " + tokens[i]);
  return f;
}

parse("(B ∧ M) → C");   // a mesma árvore da pista acima
parse("p ∧ ∧ q");       // erro: símbolo inesperado: ∧

Leiam a função implica com calma: ela chama a si mesma depois da seta, e é isso que faz p → q → r virar p → (q → r). As outras usam um laço while, que associa à esquerda. Uma versão mais completa, com mais recursos, está no exemplo de entrega da Apresentação 1.

Avaliação recursiva

Imaginem…

Uma diretora de escola que quer saber se todas as turmas fizeram a lição. Ela não visita cada aluno: pergunta às coordenadoras, que perguntam às professoras, que olham os alunos. Cada uma responde para quem perguntou, e a resposta sobe até a diretora. A avaliação de uma fórmula funciona assim: cada nó pergunta aos filhos e depois decide.

Para avaliar uma fórmula numa valoração, percorremos a árvore em pós-ordem: primeiro os filhos, depois o conectivo.

function avaliar(f, val) {          // val: { B: true, M: false, C: true }
  switch (f.t) {
    case "var": return val[f.n];
    case "not": return !avaliar(f.a, val);
    case "and": return avaliar(f.a, val) && avaliar(f.b, val);
    case "or":  return avaliar(f.a, val) || avaliar(f.b, val);
    case "imp": return !avaliar(f.a, val) || avaliar(f.b, val);
    case "iff": return avaliar(f.a, val) === avaliar(f.b, val);
  }
}

Cada nó é visitado uma vez, então o custo é O(n), com n o tamanho da fórmula. Guardem isso: verificar se uma valoração satisfaz uma fórmula é rápido. O difícil, como veremos no Caso 12, é encontrar uma valoração que satisfaça.

Notem também que a função recursiva espelha a definição indutiva: um caso por regra de formação. Provar que ela termina e está correta é uma indução estrutural (Caso 03).

Valorações como números binários

Imaginem…

Uma fileira de lâmpadas na parede, cada uma acesa (1) ou apagada (0). Lida da direita para a esquerda, a fileira é um número em binário. Contar de 0 até o maior número possível é o mesmo que passar por todas as combinações de lâmpadas, sem repetir e sem pular nenhuma.

Com n variáveis numeradas de 0 a n − 1, cada valoração é um número de n bits: o bit k diz o valor da variável k. Para percorrer a tabela-verdade inteira, basta um laço de 0 a 2ⁿ − 1. 

function tabela(f, vars) {
  const linhas = [];
  for (let i = 0; i < (1 << vars.length); i++) {
    const val = {};
    vars.forEach((x, k) => { val[x] = Boolean(i & (1 << k)); });
    linhas.push({ val, resultado: avaliar(f, val) });
  }
  return linhas;
}

Na prática, essa representação também é usada para guardar conjuntos de cartas com uma única variável inteira: cada bit é uma carta.

No DAG, uma subfórmula que aparece várias vezes vira um único nó, apontado por vários pais, como dois irmãos que moram na mesma casa e dão o mesmo endereço. Em (p ∧ q) ∨ ¬(p ∧ q), o nó p ∧ q é armazenado e avaliado uma só vez. Essa ideia reaparece na transformação de Tseitin (Caso 13).

No Detetive

Um “verificador de bloco de anotações” é só isto: uma lista de pistas em forma de árvore e a função avaliar. Dado um envelope candidato (uma valoração), o programa confere, pista por pista, se ele é compatível com tudo o que foi visto. Com 324 envelopes possíveis, testar todos leva milissegundos. É assim que o jogo da Apresentação 1 confere a escalação do time de vôlei.

Exercício 1 · Desenhem a árvore

Representem ¬p ∨ q → r como árvore e como objeto JavaScript.

Ver resposta

Pela precedência, é ((¬p) ∨ q) → r. Raiz →; filho esquerdo ∨ (com filhos ¬p e q); filho direito r.

{ t:"imp",
  a:{ t:"or", a:{ t:"not", a:{ t:"var", n:"p" } }, b:{ t:"var", n:"q" } },
  b:{ t:"var", n:"r" } }
Exercício 2 · Contando nós

Escrevam uma função recursiva que conte quantos nós uma fórmula tem. Quantos nós tem (B ∧ M) → C?

Ver resposta 
function nos(f) {
  if (f.t === "var") return 1;
  if (f.t === "not") return 1 + nos(f.a);
  return 1 + nos(f.a) + nos(f.b);
}

Para (B ∧ M) → C: 5 nós (→, ∧, B, M, C).

Exercício 3 · Bits

Com as variáveis [B, M, C] nos bits 0, 1 e 2, que valoração corresponde ao número 5?

Ver resposta

5 = 101 em binário: bit 0 = 1, bit 1 = 0, bit 2 = 1. Logo, B = V, M = F, C = V.

Exercício 4 · Estendendo o parser

Que mudanças vocês fariam no parser para aceitar também ⊕ (ou exclusivo) com a mesma força do ∨?

Ver resposta

Incluir ⊕ na expressão regular do tokenizer e, na função ou, aceitar os dois símbolos no laço: while (ver() === "∨" || ver() === "⊕") { const op = ver() === "∨" ? "or" : "xor"; i++; a = { t: op, a, b: conj() }; }. Depois, acrescentar case "xor": return avaliar(f.a, val) !== avaliar(f.b, val); na avaliação.

Para guardar
  • Fórmula = árvore: folhas são variáveis, nós internos são conectivos.
  • Ler texto tem duas etapas: análise léxica (peças) e sintática (árvore), guiada por uma gramática em BNF.
  • No parser de descida recursiva, cada nível de precedência é uma função.
  • Avaliar custa O(n); percorrer todas as valorações custa O(n · 2ⁿ).
  • Valorações podem ser números binários; DAGs compartilham subfórmulas iguais.
