Revisão rápida: o que a página anterior ensinou

Na página anterior (API REST) você construiu uma API em Node.js + Express, com rotas como GET /tarefas, POST /tarefas, PUT /tarefas/:id e DELETE /tarefas/:id, retornando dados em JSON.

Agora o foco é o outro lado da comunicação: como o front-end envia requisições HTTP para essa API e exibe as respostas na interface.

PATCH: atualização parcial de recursos

Além dos métodos mais usados (GET, POST, PUT e DELETE), existe também o método PATCH, que serve para atualizar apenas parte de um recurso.

Enquanto o PUT geralmente substitui o recurso inteiro (enviando todos os campos de volta para a API), o PATCH costuma receber só os campos que devem ser alterados. O restante é mantido como está no servidor.

Exemplo conceitual:

  • Recurso original: { "titulo": "Estudar JS", "concluida": false }
  • Requisição PATCH /tarefas/1 com corpo { "concluida": true }
  • Resultado: apenas o campo concluida muda para true, enquanto o titulo permanece o mesmo.

Em muitas APIs na prática, você verá PUT para atualização completa e PATCH para atualizações pequenas ou pontuais, como alterar só o status de uma tarefa ou um único campo de cadastro.

Diferença entre fetch e axios

fetch é uma API nativa do JavaScript para fazer requisições HTTP. Já axios é uma biblioteca externa criada para facilitar esse trabalho.

  • fetch vem no navegador; axios precisa ser instalado ou incluído no projeto.
  • fetch exige mais tratamento manual da resposta e dos erros.
  • axios costuma retornar o conteúdo já pronto em response.data.
  • axios oferece recursos extras como interceptadores e melhor padronização em projetos maiores.

Ideia central: fetch é mais próximo do mecanismo bruto; axios é uma camada de conveniência.

Outras formas de fazer requisições HTTP

Além de fetch e axios, existem outras maneiras de consumir APIs em JavaScript, embora hoje sejam menos usadas em projetos novos.

  • XMLHttpRequest (XHR): API antiga e nativa do navegador, mais verbosa e usada antes do fetch.
  • node-fetch: implementação no estilo fetch para Node.js, muito usada antes do fetch se tornar nativo em versões mais novas.
  • Outras bibliotecas HTTP: frameworks e wrappers comunitários que adicionam abstrações, organização e recursos extras.

Em termos conceituais, quase todas fazem a mesma coisa: enviar uma requisição e receber uma resposta. O que muda é o nível de abstração.

1. Consumindo APIs com fetch

A função fetch é nativa do navegador e permite fazer requisições HTTP em JavaScript sem instalar nenhuma biblioteca. Ela retorna uma Promise com a resposta.

1.1 Primeiro exemplo: GET simples

Suponha que sua API esteja rodando em http://localhost:3000 e tenha a rota GET /tarefas. O código abaixo busca a lista de tarefas e mostra no console. 

<script>
async function carregarTarefas() {
  try {
    const resposta = await fetch('http://localhost:3000/tarefas');

    if (!resposta.ok) {
      throw new Error('Erro na requisição: ' + resposta.status);
    }

    const dados = await resposta.json();
    console.log('Tarefas:', dados);
  } catch (erro) {
    console.error('Falha ao carregar tarefas:', erro.message);
  }
}

carregarTarefas();
</script>

1.2 Exibindo o resultado na tela

A seguir, um exemplo que preenche uma lista HTML com as tarefas retornadas pela API.

<ul id="lista-tarefas"></ul>

<script>
async function carregarTarefas() {
  const lista = document.querySelector('#lista-tarefas');
  lista.innerHTML = '<li>Carregando...</li>';

  try {
    const resposta = await fetch('http://localhost:3000/tarefas');
    if (!resposta.ok) throw new Error('HTTP ' + resposta.status);

    const tarefas = await resposta.json();

    if (tarefas.length === 0) {
      lista.innerHTML = '<li>Nenhuma tarefa cadastrada.</li>';
      return;
    }

    lista.innerHTML = '';
    for (const tarefa of tarefas) {
      const li = document.createElement('li');
      li.textContent = `#${tarefa.id} - ${tarefa.titulo}`;
      if (tarefa.concluida) li.style.textDecoration = 'line-through';
      lista.appendChild(li);
    }
  } catch (erro) {
    lista.innerHTML = '<li>Erro ao carregar tarefas.</li>';
    console.error(erro);
  }
}

carregarTarefas();
</script>

1.3 Enviando dados com fetch (POST)

Para criar uma nova tarefa via POST, usamos fetch com opções como method, headers e body.

<form id="form-tarefa">
  <input type="text" id="titulo" placeholder="Título da tarefa">
  <button type="submit">Adicionar</button>
</form>

<script>
const form = document.querySelector('#form-tarefa');

form.addEventListener('submit', async (event) => {
  event.preventDefault();

  const titulo = document.querySelector('#titulo').value.trim();

  if (!titulo) {
    alert('Digite um título!');
    return;
  }

  try {
    const resposta = await fetch('http://localhost:3000/tarefas', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ titulo })
    });

    if (!resposta.ok) throw new Error('Erro ao criar tarefa: ' + resposta.status);

    const novaTarefa = await resposta.json();
    console.log('Criada:', novaTarefa);
    form.reset();
  } catch (erro) {
    console.error(erro);
    alert('Não foi possível criar a tarefa.');
  }
});
</script>

2. Consumindo APIs com axios

axios é uma biblioteca que simplifica requisições HTTP. Ele funciona tanto no navegador quanto no Node.js, e já configura automaticamente os cabeçalhos mais comuns quando usamos JSON.

2.1 Como incluir axios na página

<script src="https://cdn.jsdelivr.net/npm/axios/dist/axios.min.js"></script>

2.2 GET com axios

<script>
async function carregarTarefasComAxios() {
  try {
    const resposta = await axios.get('http://localhost:3000/tarefas');
    console.log('Tarefas (axios):', resposta.data);
  } catch (erro) {
    console.error('Erro ao buscar com axios:', erro);
  }
}

carregarTarefasComAxios();
</script>

2.3 POST com axios

<script>
async function criarTarefaAxios(titulo) {
  try {
    const resposta = await axios.post('http://localhost:3000/tarefas', { titulo });
    console.log('Criada (axios):', resposta.data);
  } catch (erro) {
    console.error('Erro ao criar com axios:', erro.response?.data || erro.message);
  }
}
</script>

3. Outros métodos HTTP na prática

GET e POST são os mais frequentes, mas em aplicações reais também usamos PUT, PATCH e DELETE para completar o CRUD.

3.1 PUT para atualizar

// fetch
await fetch('http://localhost:3000/tarefas/1', {
  method: 'PUT',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ titulo: 'Nova tarefa', concluida: true })
});

// axios
await axios.put('http://localhost:3000/tarefas/1', {
  titulo: 'Nova tarefa',
  concluida: true
});

3.2 DELETE para remover

// fetch
await fetch('http://localhost:3000/tarefas/1', {
  method: 'DELETE'
});

// axios
await axios.delete('http://localhost:3000/tarefas/1');

3.3 PATCH para atualização parcial

Quando você quer alterar só uma parte do recurso, o método PATCH costuma ser mais apropriado do que PUT. 

// fetch
await fetch('http://localhost:3000/tarefas/1', {
  method: 'PATCH',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ concluida: true })
});

// axios
await axios.patch('http://localhost:3000/tarefas/1', {
  concluida: true
});

4. Tratamento de erros no consumo de APIs

Tanto em fetch quanto em axios, é essencial tratar erros: conexão recusada, rota errada, dados inválidos ou respostas 4xx/5xx.

  • Verificar o status code em fetch e em axios.
  • Exibir mensagens amigáveis para o usuário.
  • Registrar detalhes no console para facilitar o debug.
try {
  const resposta = await axios.get('http://localhost:3000/tarefas/999');
  console.log(resposta.data);
} catch (erro) {
  if (erro.response) {
    console.log('Status:', erro.response.status);
    console.log('Dados de erro:', erro.response.data);
  } else {
    console.log('Erro de rede ou configuração:', erro.message);
  }
}
