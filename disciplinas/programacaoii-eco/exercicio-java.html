O Grimório dos Heróis
Sistema de personagens para um RPG de texto
✓
▼
Difícil Herança Interfaces Exceções Arquivos DOM
🗺️ Contexto O reino de Algorithmia está ameaçado por bugs ancestrais. Você foi convocado para criar o Grimório dos Heróis — um sistema que registra, salva e exibe os guerreiros que defenderão o reino. Cada herói tem habilidades únicas, e o sistema precisa ser robusto o suficiente para sobreviver a entradas inválidas dos recrutas desastrados.

⚙️ Parte Java — O Motor do Grimório

    >Crie a interface de>Combatente com os métodos de>atacar(), de>defender() e de>getStatus() (retorna String). >Crie a classe abstrata de>Heroi implementando de>Combatente, com atributos de>nome, de>nivel e de>pontosDeVida. Implemente de>getStatus() retornando um resumo formatado. >Crie as subclasses de>Mago (tem de>manaAtual; atacar consome mana), de>Guerreiro (tem de>forca; defender reduz dano pela metade) e de>Arqueiro (tem de>flechas; atacar só funciona se tiver flechas). >Crie a exceção customizada de>HeroiSemRecursosException lançada quando de>Mago ataca sem mana ou de>Arqueiro ataca sem flechas. >Crie a classe de>Grimorio que mantém uma de>List<Heroi> e implementa:
    — de>adicionarHeroi(Heroi h)
    — de>salvarEmArquivo(String caminho): salva o de>getStatus() de cada herói em um de>.txt
    — de>carregarDeArquivo(String caminho): lê o arquivo e imprime os status no console
    — de>buscarPorNome(String nome): lança de>HeroiNaoEncontradoException se não existir

🌐 Parte Web — A Vitrine do Grimório

    >Crie uma página HTML com um formulário para cadastrar um herói (nome, tipo, nível). >Ao submeter o formulário via evento JavaScript (sem recarregar a página), exiba o herói em um card dinâmico gerado com de>innerHTML. >Cada card deve ter um botão "Remover" que, ao clicado, remove o card do DOM com de>remove(). >Use de>querySelector para validar os campos: se nome estiver vazio, exiba uma mensagem de erro vermelha abaixo do campo sem usar de>alert().
💡 Dica de integração O método de>getStatus() do Java e a exibição do card HTML são análogos — ambos "serializam" o herói em texto legível. Pense em como o mesmo dado seria representado nas duas linguagens.
📁 Entrega Arquivo de>Grimorio.java + arquivo de>grimorio.html. O arquivo de>herois.txt gerado deve ser incluído como exemplo.

CinemaCode — Plataforma de Streaming
Catálogo de filmes com recomendação e histórico
✓
▼
Difícil Polimorfismo Interfaces Exceções Arquivos DOM + Eventos
🎥 Contexto A startup CinemaCode quer lançar uma plataforma de streaming, mas o desenvolvedor principal fugiu para as montanhas com um laptop. Você herdou o projeto pela metade e precisa terminar o backend em Java E a interface web — antes que os investidores percebam.

⚙️ Parte Java

    >Crie a interface de>Reproducivel com os métodos de>play(), de>pause() e de>getDuracao(). >Crie a classe abstrata de>Midia (com de>titulo, de>ano, de>genero) implementando de>Reproducivel. >Crie de>Filme (com de>diretor), de>Serie (com de>temporadas e de>episodiosPorTemporada) e de>Documentario (com de>tema). Cada um sobrescreve de>getDuracao() com cálculo próprio. >Crie de>MidiaNaoDisponivelException lançada quando tentar dar de>play() em mídia com ano anterior a 2000 (conteúdo "fora do catálogo"). >Crie a classe de>Catalogo com:
    — de>adicionarMidia(Midia m)
    — de>exportarCatalogo(String arquivo): salva título, tipo e duração de cada mídia em CSV
    — de>importarCatalogo(String arquivo): lê o CSV e reconstrói a lista
    — de>recomendarPorGenero(String genero): retorna lista filtrada

🌐 Parte Web

    >Crie uma página com um campo de busca. Ao digitar (evento de>input), filtre em tempo real os cards de filmes exibidos na tela. >Cada card de mídia deve ter botões "▶ Play" e "⏸ Pause" que alteram o estilo do card (cor de fundo, ícone) via manipulação do DOM. >Adicione um contador no topo: "X títulos encontrados", atualizado dinamicamente com de>querySelector e de>textContent.
⚠️ Atenção O CSV exportado deve usar de>; como separador para facilitar a leitura. Trate o caso em que o arquivo não existe ao importar — lance uma exceção adequada em vez de deixar o programa travar.
📁 Entrega de>CinemaCode.java + de>catalogo.html + arquivo de>catalogo.csv de exemplo com pelo menos 6 mídias.

Banco Intergaláctico S.A.
Sistema bancário para colônias espaciais
✓
▼
Difícil Herança Interfaces Exceções Arquivos DOM + innerHTML
🌌 Contexto O Banco Intergaláctico S.A. opera em 7 colônias espaciais e aceita pagamentos em créditos galácticos. O sistema antigo foi destruído por uma tempestade de meteoros. Você tem até o nascer de Kepler-442b para entregar o novo sistema — ou os colonos ficam sem acesso às suas contas.

⚙️ Parte Java

    >Crie a interface de>Transacionavel com de>depositar(double valor), de>sacar(double valor) e de>getExtrato(). >Crie a classe abstrata de>Conta implementando de>Transacionavel, com de>titular, de>numero e de>saldo. Mantenha um de>List<String> de histórico de transações. >Crie de>ContaCorrente (tem de>limiteCredito; pode sacar além do saldo até o limite), de>ContaPoupanca (tem de>taxaJuros; método de>aplicarJuros()) e de>ContaGalactica (converte automaticamente créditos galácticos para reais na taxa 1:3,7). >Crie as exceções de>SaldoInsuficienteException e de>ValorInvalidoException (lançada para valores negativos ou zero). >Crie a classe de>Banco com:
    — de>abrirConta(Conta c)
    — de>salvarContas(String arquivo): persiste número, titular, tipo e saldo em arquivo
    — de>carregarContas(String arquivo): reconstrói a lista de contas
    — de>transferir(String numOrigem, String numDestino, double valor): lança exceção se conta não existir ou saldo insuficiente

🌐 Parte Web

    >Crie uma página de extrato: ao digitar o número da conta e clicar em "Buscar", exiba o extrato em uma tabela gerada dinamicamente com de>innerHTML. >Cada linha da tabela deve ter uma cor diferente para débitos (vermelho claro) e créditos (verde claro), aplicada via manipulação de estilo pelo DOM. >Adicione um botão "Limpar Extrato" que remove todas as linhas da tabela usando de>querySelector e de>innerHTML = ''.
💡 Dica No arquivo de contas, salve cada conta em uma linha no formato de>numero;titular;tipo;saldo. Ao carregar, use de>split(";") para reconstruir os dados.
📁 Entrega de>BancoGalactico.java + de>extrato.html + arquivo de>contas.txt de exemplo com ao menos 4 contas de tipos diferentes.

Hospital dos Robôs
Sistema de triagem e prontuário para androides
✓
▼
Difícil Polimorfismo Interfaces Exceções Arquivos DOM + Eventos
🏥 Contexto No ano 2157, robôs também adoecem. O Hospital dos Robôs de Nova Curitiba atende androides com os mais variados problemas: superaquecimento, falha de memória, corrosão de articulações. Você foi contratado para desenvolver o sistema de triagem e prontuário eletrônico antes que a fila de robôs enferrujados tome conta do corredor.

⚙️ Parte Java

    >Crie a interface de>Diagnosticavel com os métodos de>diagnosticar() (retorna String com o diagnóstico) e de>calcularCustoCirurgia() (retorna double). >Crie a classe abstrata de>Robo com atributos de>id, de>modelo, de>fabricante e de>anoFabricacao, implementando de>Diagnosticavel. >Crie as subclasses:
    — de>AndroideServico: diagnóstico verifica superaquecimento (se ano < 2140, custo base R$500)
    — de>RoboIndustrial: diagnóstico verifica corrosão (custo = R$200 × número de articulações danificadas)
    — de>RoboMedico: diagnóstico verifica falha de sensor (custo fixo R$1200, urgência sempre alta) >Crie as exceções de>RoboNaoCadastradoException e de>ModeloInvalidoException (lançada se o modelo tiver menos de 3 caracteres). >Crie a classe de>Hospital com:
    — de>admitirRobo(Robo r)
    — de>realizarTriagem(): percorre todos os robôs, chama de>diagnosticar() e imprime o relatório
    — de>salvarProntuarios(String arquivo): salva id, modelo, diagnóstico e custo em arquivo
    — de>buscarPorId(String id): lança de>RoboNaoCadastradoException se não encontrar

🌐 Parte Web

    >Crie uma página de triagem: um formulário com campos id, modelo, tipo e ano de fabricação. >Ao clicar em "Admitir Robô", gere dinamicamente com de>innerHTML um card de prontuário com cor de urgência (vermelho = RoboMedico, amarelo = AndroideServico, verde = RoboIndustrial). >Adicione um campo de busca: ao digitar o id, destaque o card correspondente com uma borda azul usando de>querySelector e manipulação de estilo. >Adicione evento de duplo clique (de>dblclick) em cada card para marcá-lo como "Alta" (muda o card para cinza com texto riscado).
⚠️ Atenção O método de>calcularCustoCirurgia() nunca deve retornar valor negativo. Valide isso dentro do método e lance uma exceção adequada se os dados de entrada gerarem um resultado inválido.
📁 Entrega de>HospitalRobos.java + de>triagem.html + arquivo de>prontuarios.txt com ao menos 5 robôs de tipos variados.

Escola de Magia Algorithmia
Sistema de notas e feitiços para estudantes de magia
✓
▼
Difícil Herança Interfaces Exceções Arquivos DOM + Formulários
🏰 Contexto A Escola de Magia Algorithmia tem um problemão: o livro de registros foi transformado em sapo por um aluno descuidado. Agora você precisa criar um sistema digital para gerenciar os estudantes, suas notas em Feitiçaria Básica, Poções e Transfiguração, e emitir o boletim mágico de cada um antes da festa de formatura.

⚙️ Parte Java

    >Crie a interface de>Avaliavel com de>calcularMedia() e de>getSituacao() (retorna "Aprovado", "Recuperação" ou "Reprovado"). >Crie a classe abstrata de>Estudante com de>nome, de>matricula e um de>Map<String, Double> de notas por disciplina, implementando de>Avaliavel. >Crie as subclasses de>EstudanteBolsista (média mínima para aprovação = 7,0) e de>EstudanteRegular (média mínima = 6,0). >Crie as exceções de>NotaInvalidaException (nota fora do intervalo 0–10) e de>DisciplinaNaoEncontradaException. >Crie a classe de>SecretariaEscolar com:
    — de>matricularEstudante(Estudante e)
    — de>lancarNota(String matricula, String disciplina, double nota): lança ambas as exceções quando necessário
    — de>emitirBoletins(String arquivo): salva nome, matrícula, notas, média e situação de cada aluno
    — de>gerarRankingAprovados(): retorna lista ordenada por média decrescente

🌐 Parte Web

    >Crie uma página de boletim: um formulário com campos nome, matrícula e as 3 notas (Feitiçaria, Poções, Transfiguração). >Ao submeter (evento de>submit com de>preventDefault()), calcule a média via JavaScript e exiba o boletim em um card gerado com de>innerHTML. >O card deve ter cor de fundo diferente conforme a situação: verde (aprovado), amarelo (recuperação), vermelho (reprovado). >Valide com de>querySelector se alguma nota está fora do intervalo 0–10 e exiba mensagem de erro no próprio campo, sem de>alert().
💡 Dica Para o boletim web, use de>document.querySelectorAll('input[type="number"]') para percorrer todos os campos de nota de uma vez e validar em loop.
📁 Entrega de>EscolaMagia.java + de>boletim.html + arquivo de>boletins.txt com ao menos 6 estudantes (3 bolsistas, 3 regulares).

Zoológico Digital de Criaturas Impossíveis
Gerenciador de espécies que não deveriam existir
✓
▼
Médio Herança Interfaces Exceções Arquivos DOM + innerHTML
🌿 Contexto O Zoológico Digital de Criaturas Impossíveis abriga seres fantásticos: Dragões que espirram HTML, Unicórnios que depuram código e Fênix que reiniciam o sistema quando tudo dá errado. O zelador foi transformado em variável local (saiu de escopo) e você precisa assumir o controle do sistema de alimentação e exibição das criaturas.

⚙️ Parte Java

    >Crie a interface de>Alimentavel com de>alimentar(String comida) e de>getNivelFome() (retorna int de 0 a 10). >Crie a classe abstrata de>Criatura com de>nome, de>especie e de>nivelFome, implementando de>Alimentavel. >Crie de>Dragao (só come "código compilado"; qualquer outra comida lança de>Comida InaceitavelException), de>Unicornio (come qualquer coisa, mas dobra o nível de fome se a comida não for "arco-íris") e de>Fenix (ao ser alimentada com nível de fome 0, lança de>CriaturaJaSaciadaException e "renasce" resetando todos os atributos). >Crie as exceções de>ComidaInaceitavelException e de>CriaturaJaSaciadaException, ambas com mensagens criativas e temáticas. >Crie a classe de>Zoologico com:
    — de>adicionarCriatura(Criatura c)
    — de>alimentarTodas(String comida): tenta alimentar todas, captura exceções individualmente e continua
    — de>salvarRegistro(String arquivo): salva nome, espécie e nível de fome em arquivo
    — de>listarCriaturasFamintas(): retorna criaturas com nível de fome > 7

🌐 Parte Web

    >Crie uma página com cards fixos para cada criatura (Dragão, Unicórnio e Fênix), cada um com uma barra de fome visual (div com largura em % manipulada pelo DOM). >Adicione um campo de texto "O que servir?" e um botão "Alimentar Todas". Ao clicar, atualize as barras de fome com de>querySelector e de>style.width. >Se a comida for inaceitável para o Dragão, exiba uma mensagem de erro animada abaixo do card (adicione/remova uma classe CSS com de>classList.add e de>classList.remove). >Adicione evento de>mouseover em cada card para exibir uma curiosidade sobre a criatura em um tooltip gerado com de>innerHTML.
💡 Dica Para a barra de fome, use um elemento assim: de><div class="barra-fome" style="width: 70%"></div>. No JavaScript, selecione com de>querySelector e altere de>style.width conforme o nível de fome (nível × 10 + "%").
📁 Entrega de>Zoologico.java + de>zoologico.html + arquivo de>registro.txt com ao menos 6 criaturas cadastradas.

Agência Espacial BugFree
Gerenciamento de missões e tripulação interestelar
✓
▼
Difícil Herança Interfaces Exceções Arquivos DOM + Eventos
🌠 Contexto A Agência Espacial BugFree planeja colonizar o planeta Kotlin-9, mas o sistema de gerenciamento de missões foi escrito em COBOL por um estagiário em 1974. Você tem 3 aulas para reescrever tudo antes do lançamento. A tripulação está na sala ao lado, nervosa, comendo chips e esperando o sistema funcionar.

⚙️ Parte Java

    >Crie a interface de>Tripulante com de>executarFuncao() (retorna String descrevendo a ação) e de>getNivelExperiencia() (retorna int 1–5). >Crie a classe abstrata de>Astronauta com de>nome, de>codigoCracha e de>nivelExperiencia, implementando de>Tripulante. >Crie as subclasses:
    — de>Piloto: de>executarFuncao() retorna manobra calculada com base no nível
    — de>Cientista: tem lista de de>experimentos; de>executarFuncao() retorna o próximo experimento da fila
    — de>Engenheiro: tem de>sistemaResponsavel; lança de>FalhaNoSistemaException com 30% de chance (use de>Math.random()) >Crie a classe de>Missao com de>nome, de>destino, de>duracaoDias e uma de>List<Astronauta>. Implemente:
    — de>iniciarMissao(): chama de>executarFuncao() de cada tripulante, trata de>FalhaNoSistemaException sem abortar a missão
    — de>salvarRelatorio(String arquivo): grava nome da missão, destino e log de cada tripulante
    — de>carregarMissao(String arquivo): lê e reconstrói os dados básicos da missão
    — de>adicionarTripulante(Astronauta a): lança de>TripulacaoLotadaException se já houver 7 membros

🌐 Parte Web

    >Crie uma página de painel de missão com uma lista de tripulantes gerada dinamicamente com de>innerHTML ao carregar a página (use um array JavaScript com os dados). >Cada item da lista deve ter um botão "Executar Função" que, ao clicado, exibe em um painel lateral a ação daquele tripulante (manipule o DOM com de>textContent). >Adicione um contador regressivo de lançamento (ex.: 10 segundos) usando de>setInterval. Ao chegar a zero, altere o fundo da página para preto e exiba "🚀 Missão iniciada!" com de>innerHTML. >Use de>querySelectorAll para destacar em amarelo todos os tripulantes do tipo "Engenheiro" assim que a página carregar.
⚠️ Atenção A de>FalhaNoSistemaException não deve encerrar a missão — apenas registrar o problema no log. Demonstre isso no de>main rodando a missão e mostrando que os outros tripulantes continuam executando mesmo após uma falha do Engenheiro.
📁 Entrega de>AgenciaEspacial.java + de>painel.html + arquivo de>relatorio_missao.txt com log completo de uma missão com 5 tripulantes.

Torneio de IAs — Quem Programa Melhor?
Campeonato entre inteligências artificiais amadoras
✓
▼
Difícil Polimorfismo Interfaces Exceções Arquivos DOM + Eventos
🤖 Contexto Todo ano, a universidade de Compilópolis realiza o grande Torneio de IAs: sistemas de inteligência artificial amadora competem entre si para ver qual delas resolve mais desafios de programação sem entrar em loop infinito. Você foi designado para criar o sistema de inscrição, pontuação e placar do torneio — e claro, ele precisa tratar todos os erros possíveis, porque IAs amadoras são imprevisíveis.

⚙️ Parte Java

    >Crie a interface de>Competidor com de>resolver(String desafio) (retorna String com a solução), de>getPontuacao() e de>getNome(). >Crie a classe abstrata de>InteligenciaArtificial implementando de>Competidor, com de>nome, de>versao e de>pontuacao. >Crie as subclasses:
    — de>IAOtimista: sempre tenta resolver, mas com 40% de chance lança de>LoopInfinitoException
    — de>IAPessimista: resolve apenas desafios com menos de 20 caracteres, caso contrário lança de>DesafioComplexoDemaisException
    — de>IAEquilibrada: resolve qualquer desafio, mas ganha metade da pontuação base >Crie as exceções de>LoopInfinitoException e de>DesafioComplexoDemaisException, com mensagens bem-humoradas. >Crie a classe de>Torneio com:
    — de>inscreverIA(InteligenciaArtificial ia): lança de>IaJaInscritaException se o nome já existir
    — de>executarRodada(String desafio): chama de>resolver() de cada IA, trata exceções, pontua quem resolver
    — de>salvarPlacar(String arquivo): grava nome, versão e pontuação de cada IA em ordem decrescente
    — de>getVencedor(): retorna a IA com maior pontuação, lança de>TorneioSemParticipantesException se a lista estiver vazia

🌐 Parte Web

    >Crie uma página de placar ao vivo: uma tabela gerada com de>innerHTML exibindo nome, tipo e pontuação de cada IA. >Adicione um campo "Novo desafio" e um botão "Executar Rodada". Ao clicar, simule uma rodada em JavaScript: para cada linha da tabela, gere uma pontuação aleatória e atualize o valor com de>querySelector e de>textContent. >Após cada rodada, reordene as linhas da tabela no DOM pela pontuação (maior para menor) sem recarregar a página. >Destaque o líder atual com um emoji 🏆 e fundo dourado, atualizando a cada rodada com de>classList.
💡 Dica de integração A lógica de ordenação do placar em Java (de>Collections.sort com de>Comparator) e a ordenação das linhas no DOM em JavaScript são o mesmo conceito em linguagens diferentes. Implemente os dois e compare a elegância de cada abordagem.
📁 Entrega de>TorneioIA.java + de>placar.html + arquivo de>placar_final.txt com resultado de ao menos 3 rodadas com 4 IAs diferentes.
