CRUD Adoção de Pets — Do Zero à Execução

Tutorial completo para entender, configurar e executar o projeto crud-adocao-pets-js. Você vai partir do zero e ter a aplicação rodando localmente, compreendendo cada camada: banco de dados, servidor Node.js/Express e front-end com fetch().

O que é este projeto?

O crud-adocao-pets-js é uma aplicação web com CRUD completo (Create, Read, Update, Delete). Ela simula um sistema de cadastro de pessoas interessadas em adotar animais de estimação.

O objetivo é demonstrar, na prática, como o navegador (front-end) conversa com um servidor Node.js (back-end), que lê e grava dados em um banco MySQL. Toda a comunicação usa fetch(), a API nativa do JavaScript para requisições HTTP.

Navegador

HTML + CSS + JavaScript. O usuário preenche formulários e vê os dados. Usa fetch() para comunicar com a API.

Servidor Node.js

Express recebe requisições HTTP, valida os dados e aciona a camada de banco. Serve também os arquivos estáticos.

MySQL

Banco de dados relacional que armazena os registros de forma persistente. Acessado com queries SQL parametrizadas.

Conceito fundamental: o navegador nunca acessa o banco de dados diretamente. Todo acesso passa pelo servidor Node.js. Isso é essencial para a segurança da aplicação.

1. Pré-requisitos

Antes de começar, certifique-se de ter os seguintes softwares instalados na sua máquina.

1. Node.js (versão 18 ou superior)

O Node.js é o ambiente de execução JavaScript no servidor. Sem ele, não há como rodar o projeto. Acesse nodejs.org, baixe a versão LTS e instale normalmente. Após instalar, verifique no terminal: 

# Verifica a versão do Node.js instalada
node --version
# Saída esperada: v24.x.x ou superior

# Verifica o npm (gerenciador de pacotes — vem junto com o Node)
npm --version
# Saída esperada: 11.x.x ou superior
O npm é instalado automaticamente junto com o Node.js. Ele gerencia todas as dependências do projeto.

2. MySQL

O MySQL é o banco de dados relacional utilizado no projeto. No Windows, você pode usá‑lo de duas formas:

  • MySQL Community Server — instalação tradicional no Windows.
  • XAMPP — pacote que já inclui o MySQL (MariaDB) junto com Apache e PHP.

Após instalar, confirme que o serviço está rodando antes de continuar.

2.1. Verificar o MySQL no Windows (instalação tradicional)

  • Pressione Windows + R, digite services.msc e confirme.
  • Procure por MySQL ou MySQL80 na lista de serviços.
  • Se o status for Executando, o serviço está ativo; se estiver parado, clique com o botão direito e escolha Iniciar.
  • Para testar, abra o Prompt de Comando e execute:
mysql -u root -p

Se o comando abrir o prompt mysql>, o MySQL está acessível.

2.2. Verificar o MySQL no XAMPP

  • Abra o painel do XAMPP.
  • No módulo MySQL, veja se o status está em Running (cor verde).
  • Se estiver Stopped, clique em Start.
Dica rápida: em qualquer um dos cenários, se o comando mysql -u root -p funcionar sem erros, o MySQL está rodando e configurado corretamente.

git --version

2. Clonar o repositório

Com o Git instalado, abra o terminal na pasta onde você quer criar o projeto e execute: 

# Clona o repositório para a sua máquina
git clone https://github.com/wilcilene/crud-adocao-pets-js.git

# Entra na pasta do projeto
cd crud-adocao-pets-js

Depois de clonar, instale as dependências do projeto com o npm:

# Instala todas as dependências listadas no package.json
npm install
O que acontece aqui? O npm lê o arquivo package.json e baixa automaticamente todos os pacotes necessários: Express, mysql2, dotenv, cors e nodemon. Eles ficam salvos na pasta node_modules/ (que não deve ser enviada ao Git).

3. Criar o banco de dados

O projeto inclui um script SQL pronto em sql/schema.sql que cria o banco de dados, a tabela humans e insere três registros de exemplo. Você tem duas opções para executá-lo:

Opção A — Via linha de comando

# Substitua "seu_usuario" pelo seu usuário do MySQL (geralmente "root")
# Será solicitada a senha logo após executar o comando
mysql -u seu_usuario -p < sql/schema.sql

Opção B — Via MySQL Workbench ou phpMyAdmin

  • Abra o MySQL Workbench (ou phpMyAdmin no XAMPP).
  • Crie uma nova conexão com o servidor local.
  • Abra o arquivo sql/schema.sql no editor.
  • Execute o script completo com o botão de execução.

Após executar, o banco terá essa estrutura:

-- Banco de dados criado
adocao_pets

-- Tabela principal
humans (
  id                   INT AUTO_INCREMENT PRIMARY KEY,
  nome                 VARCHAR(120) NOT NULL,
  email                VARCHAR(120) NOT NULL UNIQUE,
  telefone             VARCHAR(30),
  cidade               VARCHAR(80),
  tipo_residencia      ENUM('casa','apartamento','chacara','outro'),
  experiencia_com_pets TINYINT(1) DEFAULT 0,
  preferencias         VARCHAR(255),
  observacoes          TEXT,
  criado_em            TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  atualizado_em        TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
)
O campo email tem restrição de UNIQUE: não é possível cadastrar dois humanos com o mesmo e-mail. Se você tentar, o servidor retorna HTTP 409 (Conflict).

4. Configurar as variáveis de ambiente

O projeto usa um arquivo .env para guardar as credenciais do banco de dados e a porta do servidor. Esse arquivo nunca é enviado ao Git (já está no .gitignore) porque contém informações sensíveis.

O repositório inclui um modelo chamado .env.example. Copie-o e edite:

No terminal:

# No Linux / macOS
cp .env.example .env

# No Windows (Prompt de Comando)
copy .env.example .env

# No Windows (PowerShell)
Copy-Item .env.example .env

Edite o arquivo .env com seus dados:

# Configurações do banco de dados MySQL
DB_HOST=localhost
DB_PORT=3306
DB_USER=root          # seu usuário do MySQL
DB_PASSWORD=sua_senha # sua senha do MySQL
DB_NAME=adocao_pets

# Porta em que o servidor Express vai rodar
PORT=3000
Por que usar .env? Nunca coloque senhas diretamente no código-fonte. Variáveis de ambiente separam a configuração do código, permitindo que o mesmo projeto rode em diferentes máquinas com configurações diferentes — sem alterar nenhuma linha de código.

5. Executar o projeto

Com banco criado e .env configurado, você está pronto para iniciar o servidor.

Modo desenvolvimento (recomendado para estudantes)

npm run dev

O comando dev usa o nodemon, que reinicia o servidor automaticamente sempre que você salvar um arquivo. Ideal para desenvolvimento.

Modo produção

npm start

Inicia o servidor com o Node.js diretamente, sem reinício automático.

Se tudo estiver correto, você verá no terminal:

Servidor rodando em http://localhost:3000

Abra o navegador e acesse:

  • http://localhost:3000 — Formulário CRUD de adoção.
  • http://localhost:3000/api/humans — Retorna o JSON com todos os cadastros.
Dica: Deixe o terminal aberto enquanto usa a aplicação. Mensagens de erro do servidor aparecem ali. Para parar o servidor, pressione Ctrl + C no terminal.

6. Estrutura de pastas do projeto

7. Como as camadas se comunicam

O projeto segue uma arquitetura em três camadas bem definidas. Cada camada tem uma responsabilidade única e não conhece os detalhes internos das outras. Isso facilita a manutenção e o entendimento do código.

O caminho de uma requisição

Quando o usuário clica em Salvar no formulário, isso é o que acontece, passo a passo:

Passo 1 — Front-end

O JavaScript em public/app.js captura o evento de submit do formulário, monta um objeto JSON com os dados preenchidos e chama fetch(): 

const resp = await fetch('/api/humans', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ nome: 'Ana', email: 'ana@exemplo.com', ... })
});
Passo 2 — Rotas

O Express recebe a requisição de POST /api/humans e consulta o arquivo routes/human.routes.js para saber qual função chamar: 

router.post('/', HumanController.create);
Passo 3 — Controller

O controller em controllers/human.controller.js valida os dados (nome e e-mail são obrigatórios), trata possíveis erros e aciona o model: 

async create(req, res) {
  const { nome, email } = req.body;
  if (!nome || !email) {
    return res.status(400).json({ error: 'Nome e e-mail são obrigatórios.' });
  }
  const created = await Human.create(req.body);
  res.status(201).json(created);
}
Passo 4 — Model

O model em models/human.model.js executa a query SQL com parâmetros seguros (?) e retorna o registro criado: 

const [result] = await db.query(
  `INSERT INTO humans (nome, email, telefone, ...)
   VALUES (?, ?, ?, ...)`,
  [nome, email, telefone, ...]
);
return this.findById(result.insertId);
Passo 5 — Resposta

O novo registro é retornado como JSON pelo servidor. O fetch() no front-end recebe a resposta, exibe uma notificação de sucesso e recarrega a tabela com os dados atualizados — tudo sem recarregar a página. 

// Em public/app.js
const data = await resp.json();
mostrarNotificacao('Registro criado com sucesso!');
await carregarLista(); // atualiza a tabela via GET /api/humans
Por que usar parâmetros ? no SQL?
SQL Injection
Se você montar a query concatenando strings (ex.: 'WHERE id = ' + req.params.id), um usuário mal-intencionado pode injetar código SQL e destruir ou vazar seus dados.
Queries parametrizadas
Com ?, o driver MySQL trata o valor como dado puro, nunca como código. É a forma correta e segura de fazer qualquer query com dados externos.

8. Rotas da API REST

A API segue o padrão REST: cada verbo HTTP representa uma operação diferente sobre o mesmo recurso (/api/humans).

Método Rota Operação Retorno
GET /api/humans Lista todos os registros Array JSON — HTTP 200
GET /api/humans/:id Busca um registro por ID Objeto JSON — HTTP 200 ou 404
POST /api/humans Cria um novo registro Objeto criado — HTTP 201
PUT /api/humans/:id Atualiza um registro existente Objeto atualizado — HTTP 200
DELETE /api/humans/:id Remove um registro Sem corpo — HTTP 204

Testando a API pelo navegador

Com o servidor rodando, você pode testar a rota de listagem diretamente no navegador: 

http://localhost:3000/api/humans

Para testar POST, PUT e DELETE (que precisam de corpo na requisição), use o Thunder Client (extensão do VS Code) ou o Insomnia / Postman.

Exemplo de requisição POST com fetch() no console do navegador

Abra o DevTools (F12 → Console) com o servidor rodando e cole:

fetch('/api/humans', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    nome: 'Teste Silva',
    email: 'teste@exemplo.com',
    cidade: 'Joinville',
    tipo_residencia: 'casa',
    experiencia_com_pets: true
  })
})
.then(r => r.json())
.then(console.log);
Exemplo de requisição DELETE 
// Substitua 1 pelo ID real do registro
fetch('/api/humans/1', { method: 'DELETE' })
  .then(r => console.log('Status:', r.status)); // esperado: 204

9. Como o front-end funciona

O front-end é composto por três arquivos na pasta public/, servidos diretamente pelo Express como arquivos estáticos:

index.html — A estrutura da página

Define o formulário de cadastro, a tabela de listagem e a seção explicativa da API. Não contém nenhuma lógica JavaScript — toda a interatividade está em app.js.

style.css — A aparência

Folha de estilos com variáveis CSS (:root), responsividade via CSS Grid e media queries. Nenhuma biblioteca externa é necessária.

app.js — A lógica do front-end

Este é o arquivo mais importante do front-end. Ele realiza as quatro operações CRUD:

CREATE e UPDATE — função salvar()

Detecta automaticamente se é uma inserção (formulário sem ID) ou edição (formulário com ID preenchido). Usa POST ou PUT conforme o caso.

READ — função carregarLista()

Chamada ao carregar a página e após qualquer alteração. Faz GET /api/humans e renderiza os resultados na tabela via DOM.

EDIT — função carregarParaEdicao()

Ao clicar em Editar, busca o registro por ID (GET /api/humans/:id) e preenche o formulário com os dados atuais. O botão Salvar vira "Atualizar".

DELETE — função remover()

Solicita confirmação antes de enviar DELETE /api/humans/:id. Após a remoção, recarrega a tabela automaticamente.

Padrão importante usado no app.js: delegação de eventos.

// Em vez de adicionar um listener para cada botão da tabela,
// um único listener na tabela detecta qualquer clique:
tabelaBody.addEventListener('click', e => {
  const btn = e.target.closest('[data-acao]');
  if (!btn) return;

  const { acao, id, nome } = btn.dataset;

  if (acao === 'editar')  carregarParaEdicao(id);
  if (acao === 'remover') remover(id, nome);
});
// Isso funciona mesmo para linhas adicionadas dinamicamente,
// porque o listener está no elemento pai (tabelaBody), não nos botões.

10. Erros comuns e como resolver

Erro: connect ECONNREFUSED 127.0.0.1:3306

O Node.js não conseguiu conectar ao MySQL. Causas prováveis:

  • O serviço MySQL não está rodando — inicie-o pelo XAMPP, Services ou sudo service mysql start.
  • A porta no .env está errada (padrão é 3306).
  • O usuário ou senha no .env está incorreto.

Unknown database 'adocao_pets'

O banco de dados ainda não foi criado. Execute o script SQL:

mysql -u root -p < sql/schema.sql

Cannot find module 'express'

As dependências não foram instaladas. Execute:

npm install

Error: listen EADDRINUSE :::3000

A porta 3000 já está em uso por outro processo. Duas soluções:

  • Encerre o outro processo que usa a porta 3000.
  • Mude a porta no .env: PORT=3001 e reinicie o servidor.

HTTP 409 — E-mail já cadastrado

O campo email na tabela tem restrição de UNIQUE. Tente cadastrar com outro e-mail ou remova o registro existente antes de reutilizá-lo.

A tabela da página aparece vazia mesmo após cadastrar

  • Verifique no console do navegador (F12) se há erros de rede.
  • Confirme que o servidor está rodando (npm run dev).
  • Acesse http://localhost:3000/api/humans diretamente para ver se a API responde.
Dica geral: Sempre que algo não funcionar, verifique dois lugares: o terminal (erros do servidor Node.js) e o console do navegador (F12 → Console), onde erros de JavaScript e de rede aparecem com detalhes.
